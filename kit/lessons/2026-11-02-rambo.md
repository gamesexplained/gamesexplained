**A protected loader read from the drive's side.** The disk's loader (Ocean's XROM protection) fell back to `READY.` in VICE
v3.13.2 and v3.14.0 under every drive setting tried. Reading the C64's side
found nothing wrong: its second stage was correct and only a later file was
missing. What explained it was the drive's own code, which hooks the DOS job
loop and renumbers tracks and sectors. The text monitor could not show it:
its `chis` was too slow for the moment that mattered, and two raw socket
sessions wedged it. A snapshot saved at the C64's next LOAD holds the
drive's RAM in its `DRIVECPU0` module, 114 bytes after the module's name,
and that gave the decrypted drive code in one read. The failing step was
then a file lookup the emulated DOS answers "62, FILE NOT FOUND"; sending
the game's own loader back once to the same call loaded every later byte
from the disk through the game's code.
