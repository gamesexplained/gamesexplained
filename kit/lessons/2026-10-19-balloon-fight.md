## 0.0.257 · 2026-10-19 · Balloon Fight (NES) · Zihe Jia (icyriver2023) with Claude Fable 5.1

- **Name a request bit by the routine that takes it, never by the routine that sets it.** Balloon Fight's game code sets bits in four sound-request bytes, and the driver reads them in its own order: a flap set as bit 4 was answered by the routine two bits along, a bit set for the thunder was never read at all, and five of fourteen effects were named after the wrong routine until each bit was poked into a paused game and the driver's writes recorded. When a routine leaves a number for another to act on, read the taker's dispatch (its shifts and branches) before writing what each value means, and where the emulator can record the taker's output, record it for every value.
- **A split pointer table with a label on its second half is not `lo_hi_address`.** regenerator2000 0.9.20 pairs each labelled stretch with its own halves, so a table whose high bytes carry an automatic label mints addresses from the wrong pairs, in the middle of routines; the coverage queue showed them as bare runs inside described code. Type such a table `byte` and say in its comment how the halves pair.
- **Verify a port against the game's input timing, not only its arithmetic.** The flight port matched gravity, the flap and the limits to the byte and still failed the lockstep: the game reads the pad every third frame and refuses a flap for nine frames after one. Run the game's own routines for the whole loop the mechanic lives in, with the counters that gate it, and compare every frame.
- **A machine whose picture lives in the video chip's own memory has no picture in the listing.** On the NES the tiles, the nametables and the palette are the PPU's, outside the CPU's 64 KB, so a page cannot draw from the listing as a C64 page does; it carries the pieces it draws as data (`kit/nes/snapshot.py`'s `ppu` and `oam`). The cheapest oracle for a level renderer is the emulator's own nametable, captured for every layout by stepping the level index and clearing the level, and compared cell by cell below the status bar; the first game's renderer was wrong in a propeller's attribute quadrant and a bonus round's sprite palette until that comparison said so.
- **A pass address must be reached once a pass, and a routine's RTS can be reached twice.** The NES lockstep's pass was put at the RTS of the game's wait for the frame, and the game reached it a second time each pass through a branch in the pause routine that returns via that RTS, so the lockstep saw a pass the port never yielded. Put the pass at the instruction after the wait loop, which only the loop's exit reaches, and look for every `beq`, `bne` and `bcs` whose target is the RTS before naming it.
- **A port's routines must return the carry where the game's leave one that matters.** Four of Balloon Fight's routines add with the carry a previous routine left, the last `lsr` of the random generator and the last `adc` of the sprite drawer among them, and the lockstep showed each as a single byte off thousands of frames apart. When a routine's `adc` has no `clc` before it, trace the carry back through every return to the instruction that set it, return it from that routine and pass it on; and read a byte the handler writes through `irqBytes` wherever the main loop reads it, so a frame the loop cannot finish in time does not part the two.
- **A page's data must not be the program.** The first game's levels page carried the whole PRG ROM as its data, since the renderer read the layout tables through the ROM's addresses, and no check noticed. Build an image with every code byte zero (the listing says which bytes are code) and embed that: the tables keep their addresses, and a reader cannot rebuild the game from the page.
- **A port written as generators can rewind from the top of its main loop.** A generator cannot be copied, so a Play tab's port cannot be saved at any moment; but where the game waits for the frame at the top of its main loop, the port's stack holds nothing but the loops above it, and a page can save the RAM, the picture chip and its own clock there and later start a generator that enters the same loop and carries on as the code above it would. Save nowhere else: Balloon Fight's demonstration runs the same phase loop under the title's, and a state saved in it came back into the wrong caller. Hold the restore with a test that runs a restored copy beside the original for thousands of frames and compares every byte and pixel.
