## next · 2026-11-18 · Turrican (C64) · air with Claude

- **A tune's player can read music from outside the tune.** Turrican's
  ending tune lists 21 sound programs, but one program ends by jumping
  to a 22nd, and the 22nd place in the table of their addresses holds
  `$1808`, inside the engine's code that scrolls the screen. In the game,
  a voice plays those 191 bytes of code as notes for up to four seconds
  at a time, which a load watch in VICE confirmed (18 November 2026).
  The page first embedded only the ending's module, and its tune left
  the game's 14 frames in. The test that caught it ran the game's own
  player on the whole memory of that moment, the ending's listing over
  the parts beneath it, and compared every call's writes with the
  page's driver; a test that runs the player on the page's own bytes
  passes either way. So a page's tune is held to the player run on the
  part's whole image, and any read outside the embedded bytes is either
  given to the page or explained.
- **Drawing from the listing is a second reading of it.** The 80-comment
  sample found 8 wrong. Building the Graphics tab, which draws each
  sprite in the mode its comments gave, found 9 more that the sample
  had not drawn: eight read the game's own mode flag backwards, because
  the multiplexer turns it into the video chip's bit through the carry.
  The pictures looked wrong before any comment was checked, and VICE's
  sprite registers settled which way the flag ran. A widget whose
  output can be compared with the game's screen is worth comparing,
  even when the listing has passed its sample.
