## next · 2026-10-19 · Zork I (Apple II) · air with Claude

- **Compare every limit a caller passes with the room it describes.**
  Zork's story tells the interpreter it may write 120 words into a parse
  buffer with room for 59. The interpreter honours the limit, so each
  routine reads as correct on its own, and the 60th word writes over the
  size of the buffer after it: from then on the game reads one letter of
  every line. A line of sixty commas, typed live, showed it. For each
  count, length or size one routine hands another, find the buffer it
  governs and work out how much fits.
- **Follow a recursive call's result to where it is used.** The routine
  that adds up the trophy case calls itself for each container in it,
  and the inner total goes onto the stack and stays there: the next
  instruction moves on. A treasure left in a sack in the case scores
  nothing, which a live test confirmed. Where a routine calls itself,
  check that the result reaches the total.
- **An interpreted game's program can be mostly outside memory.** The
  snapshot held Infocom's interpreter and the first 18 KB of an 80 KB
  story; the rest is read from the disk a page at a time and was in no
  snapshot. Coverage of 100 % was of what memory held. When a game is an
  interpreter and a program for it, say in `TODO.md` and on the page
  what the listing covers of the program (#428).
