## 0.0.65 · 2 October 2026 · Mr. Hat · jankfoundry with Claude

**A freezer backup's stack leads back to the game's entry.** Mr. Hat's
tape is a freezer backup of the game on its title screen. The freezer
resumes with an `RTI` from the stack page, and the return addresses
above it were the game's own call chain at the moment it was frozen: the
fire loop, the title routine, the entry, and BASIC's `SYS`. The entry
they led to rebuilt the same machine byte for byte when the game was
restarted there. The C64 reference now says to read that stack.

**Test a control from a standing start.** The run held the stick up on
a snapshot that happened to be mid-jump, wrote down "up jumps", and
briefed nine annotation agents with it. In Mr. Hat fire jumps, and up
only climbs ladders. Four agents corrected it from the code before the
lead did. `20-features` now says to try each control from a still moment,
with and without the input, and to record the sprite per frame.

**Write as you go.** The account's usage limit stopped all nine agents
twice, once before they had written anything, because each meant to
write its labels in one batch at the end. Resumed from their own
context, they finished. The brief now asks agents to write each routine
as they understand it, and `50-coverage` says to resume a stopped agent
rather than start a new one.

**PETSCII text may space with cursor controls.** Lupenio's leftover text
in Mr. Hat separates its words with `$1D`, cursor right, and its lines
with `$11`, cursor down. A sweep for printable characters found the words
run together. The C64 reference now lists the controls to expect.

**Count the instances before writing "every" or "only".** The
maintainer's review traced twelve of Mr. Hat's page claims and found
five wrong, and a full audit found six more; nearly all were one room or
one test written up as the game's. A collision list was one of four
tests; "room 1's tune" played in every room; a bug's effect was worked
out from how many callers passed a flag, without reading what each
caller had already checked. `60-verify` now asks for every instance to
be listed before a claim about all of them.

**Read the findings against each other.** Mr. Hat's facts said, in one
section, that room 5's object opens the way to the end and, in another,
that room 5's pickups look impossible to take. Nobody put the two
together until an audit did; tried live, the object cannot be taken, and
the game ends anyway because a second switched-off colour store leaves
the way open. A finding that something cannot happen is worth checking
against everything that depends on it.

**Measure the comments, not only the page.** A random sample of 60 of
Mr. Hat's 1,268 listing comments, checked against the bytes by an agent
that wrote none of them, found a wrong detail in 15 (25 %). A full pass by
nine fresh agents corrected 235, and a second, independent sample found
2 in 60 (3 %). The annotation step's own spot check, one claim per agent,
had not shown the problem. `60-verify` now asks for the sample before a
game is called done.
