The game is a Z80 program in five parts: the engine, always in memory, and above it the wizard designer or one of the three scenarios, about 29,800 bytes of code in all. The port is the same program written again in JavaScript, one function for each of the game's 412 routines, reading and writing the game's variables at the game's own addresses. The page runs only the port.

The game can stop for good. In a game against the computer, a computer creature standing on more than ten objects sends its search for the one it wants on through memory, and the mark it leaves can land on the turn loop's own instruction: the loop then counts up a byte of the ROM instead of the player, and the screen stays blank for ever (Discoveries tells the whole story). The port reads that instruction's operand from memory, as the Z80 does, so it hangs in the same place.

The game prints in the ROM's font and turns KEY-SCAN's codes into characters with a copy of the ROM's key table. The page carries those two pieces of the 48K ROM ($3D00-$3FFF and $0205-$022B) and nothing else of it; KEY-SCAN, LD-BYTES and SA-BYTES, as far as the game uses them, are ported with the game's own routines.
