# Ant Attack — kit feedback

## Skill text that changed what I did

- `50-coverage`: "Is the picture loaded or drawn?": compared entry and play, then traced the scene-buffer writers before excluding generated bytes that the tape happened to contain.
- `60-verify`: "It was going to happen anyway.": reloaded the same play state for key/no-key controls instead of interpreting the next screenshot as an input effect.
- `65-inputs`: "Replay it on a second machine": replayed short and combined-key grenade routes on both the emulator and the kit's 48K machine before describing the extra fuse settings as reachable.
- `10-orient`: "Read the file's header before trusting its name.": checked the TZX signature and block structure before choosing a loading route.

## What changed in the kit

None. The failures encountered were visible and have reproducible notes
in agent-history.md. No general workflow change was established.

## What cost the most time

A dedicated timed-beeper recording command would have saved the most time:
the run located the ROM BEEP OUT instruction, captured its T-state/port
values with a non-stopping checkpoint, and adapted them to the existing
Spectrum sound model's timed-write interface.

## Candidates

- A path containing a space is accepted by the Python client's file-exists check but rejected by ZRCP smartload as an unknown format. This run used a space-free copy. A client quoting/argument test would be useful, but the evidence here is one game and no silent failure occurred.
- Shape comments should describe the source records rather than refer to a page still being built. The checker found fifteen instances of that premature claim, and the run removed their shared sentence. The existing verification and sample rules already cover it.

## Platform observations

Linux x86_64 matched the recorded 47/50 emulator result; footprint was
clean. SDL 1.2 was already present. No system packages or shell settings
were changed. SkoolKit occupied about 18 MB of disk; the launcher's 103 MB
report counts virtual-environment paths differently. The three emulator
limitations have workarounds in the platform notes and are not new asks.
