The game is a Z80 program of 25,132 bytes of code, about half in the 128's main memory and half in its bank 3. The port is the same program written again in JavaScript, one function for each routine the game calls and each place its tables jump to, 452 in all, reading and writing the game's variables at the game's own addresses in the 128's own banks. The page runs only the port: the game's code is in the tests, as the original the port is held to.

CheckWhat it showed
Each routine aloneSixteen test files take each routine at the moments the game itself calls it, in 148 saved moments of play, some with registers and variables changed at random. The port's routine and the game's own, on the kit's Z80, run from the same machine, and every byte of the eight banks, the paging, the AY's registers and the writes to the chips must come out the same.
The whole program in lockstepThe port's program runs beside the game's, pass by pass: from the loader's hand-over through the control selection and 1,500 passes of play, and from each of the 148 moments for 400 passes, with the stick, fire and the menus played at random. Every byte of the eight banks, the paging, the border and the AY was the same at every stop, but for the stack and the two bytes where the sound driver keeps the stack pointer.
Area 14 and the ROMArea 14's map and the mask of one frame of the arm that reaches out of a rock run on past the end of memory into the 128's ROM. The page carries those 171 bytes of ROM 0 and nothing else of it, and the port reads them where the game does. The lockstep runs through area 14.
The page's memoryThe page carries the game's memory as the loader leaves it. Of the main memory's 12,863 bytes of instructions, all but 1,068 are set to zero: 858 the game rewrites and reads as variables, and 210 it reads as data, the start-up code that becomes the sprites' visibility mask and tune 18's code, which tune 17 plays as notes. Bank 3 is carried whole, its code included, because the game's random numbers are bank 3's bytes read one after another. The page's machine on that memory and on the whole memory ran the same, frame for frame, from the hand-over for 2,100 frames and from 37 of the moments for 600 frames each, with input at random.
The paceThe port executes no instructions, so the page charges each stretch of the main loop, each routine, and each byte, row and character it copies or draws the T-states they cost the game, fitted on 22,798 passes timed on the kit's model of the 128: from the hand-over and from the moments, with walks and runs that drag the windows and scroll the view. On 14,799 passes it was not fitted on, four in five come within 1.1 % of the game's time. From 25 other moments, with the same walks, runs and shots on both for 30 seconds, the page takes within 4 % of the game's time for the same passes, 1.6 % less on average, and from the hand-over it reaches play within 2.2 % of the game's time.
