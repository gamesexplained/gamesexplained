01 · The port

Every routine of the game, checked against the original

The game is a Z80 program of about 20,000 bytes of code. The port is the same program written again in JavaScript, one function for each of the game's 89 routines, reading and writing the game's variables at the game's own addresses. The page runs only the port: the game's code is in the tests, as the original the port is held to.

CheckWhat it showed
Each routine aloneEight test files take each routine at the moments the game itself calls it, in 208 moments of play saved from the emulator; others run on inputs made at random: the arithmetic on random operands, keys and the joystick held at random, and scripts of random instructions. The port's routine and the game's own, on the kit's Z80, run from the same machine, and every byte of memory, the border and the beeper's writes must come out the same.
The whole program in lockstepThe port's program runs beside the game's, pass by pass: from the loader's hand-over through the security question and the control options into play, and from each moment of play for 150 passes, with the keys played at random. Five more runs force the ways out of play the sessions seldom reach: the clock running out, the energy, the shield, the information screen, and abandoning the game from it, each through the game over and back to the menu. Every byte of memory and the border were the same at every stop, but for the stack.
The ROMCollecting a rig in Amethyst before any rig of the game has been put down reads the gas from a table whose pointer is still 0: the ROM's first byte, $F3. The page carries that one byte of the 48K ROM and nothing else of it.
The page's memoryThe page carries the game's memory as the loader leaves it, with 20,091 bytes of instructions set to zero; it keeps 288 bytes of code that the game also keeps state in, operands it rewrites and the two bytes the security question mends. The page's machine on that memory and on the whole memory ran the same, frame for frame, from the hand-over and from the moments of play with random keys.
The paceThe port executes no instructions, so the page charges each stretch of the main loop, each routine, and each row, byte and character it fills or prints the T-states they cost the game. The heaviest routines are priced from their own T-states, measured on the game: the span filler by the rows, bits and bytes it fills, a polygon's edges by their rows and steps, the vertex rotation by its multiplications, the painter's sort by its comparisons and swaps, and nine routines whose cost a call holds within 10 % at that cost. The rest is fitted around them on 16,389 passes timed on the kit's model of the 48K; the interrupt is fitted the same way, with each sensor it checks and each beam it draws. On 2,399 passes it was not fitted on, the median pass is 0.1 % short of the game's time, and seven in eight are within 5 %. Over 60 passes from each of 153 moments of play, once with random keys and once with a fixed round of walks, turns, looks up and down and moves of the crosshair, 296 of the 306 runs take within 5 % of the game's time; the slowest, in Mitral, takes 9 % longer. From moments of play, with that round of commands on both for 30 seconds, the page takes within 5 % of the game's time for the same passes.

02 · Fast CPU

The game on a much faster processor

Driller moves you a fixed step each time its main loop goes round, a pass. On a Spectrum a pass takes from a seventh of a second to nearly two, most of it spent drawing the view, and close to half a second in the middle, so in Amethyst you walk in steps of 250 of the game's units and turn 15 degrees at a time. A Spectrum with a much faster processor would make dozens of passes a second and take a whole step each time. With Fast CPU on, the page plays the game as such a machine would if it were built to stay playable: a new frame 60 times a second, and you move as fast as the Speed sets, whatever is in view.

A pass on each tick, 60 a second

The game keeps its time by the Spectrum's frame interrupt, 50 a second: it takes a second off the clock to the meteor strike every 50 frames, a unit of energy every minute, and fires the laser beacons. Fast CPU counts ticks of its own, 60 a second, in the Spectrum's T-states: 58,333⅓ of them to a tick. With Fast CPU on, each pass starts on a tick, and never more than one pass on the same tick. The pass's own work takes no time, as on a processor fast enough to finish it long before the next tick.

Sixty is the refresh rate of most displays. A Spectrum's screen shows 50 frames a second, and a pass on each of those would show unevenly on a 60 Hz display, one frame in five held for two refreshes. Each refresh of your display, the page runs the passes it owes the game for the time since the last refresh, and shows the screen as the last of them left it in the same refresh, so the screen is always the game's newest. When no key is down the game waits for one, as on a Spectrum, and a key that goes down is taken at once.

A refresh runs at most four passes. A display as slow as 15 Hz still keeps up with the clock, and a refresh that comes late, while the browser was busy elsewhere, starts the game again from where it stopped rather than racing to catch up. Counted in the Spectrum's T-states, the same keys pressed on the same passes make the same game on any display.

The clock keeps absolute time

The interrupt runs in the Spectrum's time with Fast CPU on or off, so everything it counts runs as on a Spectrum, in seconds: the clock, the energy a minute, the laser beacons' shots. So does every wait inside a pass, such as the game's pause after a change of the turn size, and every sound. The processor drives the beeper itself, and while an effect plays the game does nothing else, so the laser's sound, about a fifth of a second, holds the pass that fires as it holds a Spectrum's, and the screen shows what a Spectrum's shows meanwhile: the four lines of the beam, which the game rubs out when the sound ends. The next pass starts on the first tick after. The security question, the control options, the information screen, drilling, the end of a game and the demonstration run at the Spectrum's speed. A minute of play is a minute on either machine.

The Speed sets how far each pass takes you

Fast CPU makes many passes where the Spectrum made one. Anything the game counts in passes would happen that many times as often, so each pass takes only a share of a step. The Speed slider sets how many ticks one Spectrum step takes, K. Each pass walks, turns, looks or rolls 1/K of the Spectrum's step, through the game's own code for a step, and carries the part of a unit left over to the next pass. Holding a key for K ticks moves you exactly one Spectrum step, whatever is on screen. You travel as fast as a Spectrum that made 60/K passes a second, and see 60 frames.

A Spectrum with a faster processor would be nowhere slower than a Spectrum, so even 1× keeps up with a Spectrum at its quickest. Timed on the game's own code from 89 moments of play, a Spectrum's quickest pass takes 7.2 of its frames, 0.144 s, turning in Fluorite while looking down at the ground. A quarter turn is six steps: 0.8 s at 1× anywhere, where a Spectrum takes about two and a half seconds with a pass in the middle of its range.

What the game counts in interrupts stays as it is. So at any one Speed you cover the same ground in each second of the clock whichever way you face, where on a Spectrum you cover less while the view is slow to draw. A faster Speed covers more ground before the meteor strikes, as a faster Spectrum would. Moving the slider turns Fast CPU on, and the page remembers the Speed.

Held down, the laser fires once a step. Its sound holds the pass that fires, so it fires a shot every 0.32 s at 1×, where a Spectrum fires every 0.33 s, every 0.25 s at 2× and every 0.22 s at 4×. The page holds every key down for at least three of the Spectrum's frames, so that a pass reads it.

The view between two of the game's angles

A share of a turn leaves you at a fractional angle, between two of the game's 72. The game keeps a sine and a cosine for each of its angles, in 64ths. Between two angles the page takes each of them part of the way to the next angle's, rounded to the nearest 64th, and the game builds its view from them with its own code. A walk at a fractional heading goes along that heading. At the game's own angles the screen shows the game's own frame.

Walls stop you as they stop a Spectrum

When a step runs into an object, the game cuts the step short. With Fast CPU each share of a step is cut on its own, so a walk into a wall at an angle could creep along it where a Spectrum stops. In Driller it rarely does.

03 · Differences

What differs from a Spectrum

With Fast CPU off, the game plays as it does on a 48K Spectrum, at the 48K's own speed. These are the places where the page cannot be the machine, and what it does instead.

On a SpectrumOn this page
The interrupt can fall between any two instructions of the main program.The interrupt runs between two of the port's routines, at the clock's time for it. The bytes the interrupt changes and the main program reads in the middle of a routine (the wait counter, the clock's frame count, the minutes, the energy and the shield, and the sensors' beams) are read after the interrupts due by then have run.
Each instruction takes its T-states, and a pass takes as long as its drawing does.The port executes no instructions. Each stretch of the main loop, each routine and each row and byte it fills costs what it cost the game, measured or fitted on the game's own timings (01, The pace), so a pass takes about as long as on the Spectrum: within 5 % but for a few scenes, the slowest of them in Mitral, 9 % slower.
A sound effect plays with the interrupts off, and the frames it lasts are lost to the game's clock.The page's effects take the game's time with the interrupts off too, and lose the same interrupts, as does a sensor's hit, whose sound plays inside the interrupt.
The beeper is toggled from the effects' timing loops.The site's model of the beeper plays the port's writes to it, each at the T-state the game's loops make it, as the frame is shown.
The ULA draws the screen a line at a time as the beam crosses it.The page takes the screen whole at the moment the beam would reach its first line, so a change made while the beam is drawing shows a frame later, all at once.
The information screen's S and L save and load a position on tape.S gives a .tap file to download, with the game's two blocks; L asks for a .tap file and gives the game its blocks in turn. Cancel is BREAK.
The joystick is a Kempston interface, a Sinclair stick or the cursor keys, as the control options choose.The arrow keys, and the pad under the screen, are whichever joystick the control options chose, with Left Ctrl for fire; every other key is the Spectrum's own.
