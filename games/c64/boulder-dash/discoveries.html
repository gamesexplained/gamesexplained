The caves are never random, the tune hides in the graphics, and a rock takes four tries to push.

01 · Secret: the same cave every time

Seeds make the caves repeatable

The cave's dirt, boulders and diamonds look random but are not. Each of a cave's five levels has a seed byte in its header, and a small generator started from it places every cell the same way each time ($7085, $8029). The recipe is on the Maps tab, and the page redraws any cave from it. A player who learns where the boulders sit in cave A, level 1, can rely on it. The routine for random bytes elsewhere in the game is a different one, driven by timers, and is used for the creatures, the amoeba and the sound ($6E68).

02 · Secret: the tune is in the pictures

Tune bytes double as characters

The title tune, 256 bytes of note numbers, starts at $5FE8. So does the tile character set. The start-up copies 1,024 bytes from there to $3000 ($8D11), and the music routine reads the same bytes at their original address ($8754). The first thirty-two tile characters are therefore the tune. Whether the sharing was designed or a happy accident is not known.

03 · Quirk: a boulder takes four tries

The push succeeds one time in four

When Rockford walks into a boulder beside him, the game takes a random byte and moves the boulder only when its low two bits are zero ($7543). The same step does not count as a move on the other three tries, so the player seems to lean on the boulder until it gives.

04 · Quirk: the easy levels are slow

Speed is a delay loop

The game has no clock for its pace. After each row of the cave, a loop of idle counts runs, for 12, 6, 3, 1 or 0 passes depending on the level ($8065). Level 5 runs flat out.

05 · The copier

A packager’s stub in front of the game

The disk image holds one 65-block program. It starts with a BASIC line, SYS 2088, which enters a copier at $0828. The copier moves 16,384 bytes from $0870 to $5000 in a loop and jumps to the game's real start at $8E69. The game's own code therefore never runs at the addresses it was loaded at, and the same entry is the target of the NMI vector the game sets, so the RESTORE key restarts the game. That was traced in the code and not tried.

06 · Open questions

What could not be explained

  • Object $3A is drawn as amoeba by the table at $5F28, but the test for Rockford in $714C counts objects $38 to $3A. Which one it is in play was not found.
  • Bytes 22 and 23 of each cave header have no use found.
  • Eight 192-byte blocks at $68E8-$6E67 are copied to $3840 at start, and no routine that reads them was found.
  • Twenty-three bytes after the program at $8F4E spell “:SK3A” and “:SK4” between other bytes. Nothing refers to them.
  • Fire in play can end the cave in some state ($815B); the condition was not tried.
