# Map 20, Base Cochise, the reactor — verified technical facts

The level of Base Cochise that holds "the main power panel of the reactor core" (message 19), signed "An arrow shaped plaque on the wall points to the right. The message on it reads -REACTOR CORE ROOM-." (message 28). It also holds a conveyor belt of repair machines (messages 44-52), a room of robots that wrestle (message 1), four stations that take four keys and arm the self-destruct (messages 4-11) and an escape pod (message 8). Map 18's exit 9 leads in at (16,16). Map 17's exit 12 (map-17 `$3C7E`) leads to (16,10), but no square, change or code of map 17 names it. It is 32 x 32 squares, stored on side 4 of the disks as 35 pages from T15/L19 (track 15, logical sector 19), entry 20 of the map directory at T35/L14 (engine `point_at_maps`, `$28CE`). Engine `enter_map` (`$25BD`) loads it to `$3400-$56FF` and unpacks its tile layer to `$DE00-$E1FF`. It is drawn with tile set 8 (tiles-8). Squares are given as (column, row). Every address here is this map's unless a part is named beside it.

## Its own code

The code list, header word 19 (`$3A26`), is at `$4013` and has eight entries, `$402B`, `$403C`, `$404D`, `$405C`, `$406B`, `$4088`, `$408B` and `$4023`. Action squares 0-8 (`$3FFD-$4012`) run entries 0-5, 5 again, 6 and 7. An action square whose record byte 0 is below `$80` runs entry n (game `run_action` `$8845`: engine `api_map_class_entry` `$0428` with Y = `$10` at game `$885E`, then game `jump_work_ptr` `$AC69`), entered with the carry clear (the ASL at engine `$09D5`). When the routine returns, a set carry has the view redrawn (game `$8872`); then the record's change at +1/+2 is applied to the party's square (game `$8840`, `alter_party_square` `$B105`), and a written change runs the new square at once (game `run_square_action`, `$ACC1`).

- `$402B` encounters_more_often, action square 0: `$3A2F` − 2, unless `$3A2F` is 0 (`$402F`) or the result is 0 or has bit 7 set (`$4034`, `$4036`).
- `$403C` encounters_less_often, action square 1: `$3A2F` + 2, unless `$3A2F` is 0 (`$4040`) or the sum is 100 or more (`$4045`).
- `$404D` more_monster_types, action square 2: `$3A31` + 1, unless that is 12 or more (`$4054`).
- `$405C` fewer_monster_types, action square 3: `$3A31` − 1, unless the result is 0 or has bit 7 set (`$4063`, `$4065`).
- `$406B` arm_self_destruct, action square 4: copies the elapsed count `$04-$06` into engine `countdown_start` (`$F4FA-$F4FC`), sets engine `countdown_armed` (`$F4F9`) to 1 and `$3A2F` to 0 (`$406B-$4083`), calls engine `api_screen_shake` (`$044C`) at `$4085` and runs on into explosion, which jumps there again.
- `$4088` explosion, action squares 5 and 6: a jump to engine `api_screen_shake` (`$044C`): engine `screen_shake` (`$0746`) plays sound 0 and jolts the screen twelve times. It returns the carry that random_byte's last ADC left (engine `$24EC`; nothing after the last jolt at engine `$0764` changes it), so whether the view is redrawn after it and after arm_self_destruct (game `$8872`) is chance.
- `$408B` show_countdown, action square 7: takes the low two bytes of the elapsed count less those of engine `countdown_start` from 240 (`$408B-$40AA`), keeping the result in the operands countdown_low_op (`$40AE`) and countdown_high_op (`$40FC`). The low two bits pick the seconds, 0, 15, 30 or 45, from quarter_seconds (`$4102`) into countdown_seconds_op (`$40ED`) (`$40AD-$40B5`), and two shifts leave the minutes (`$40B8-$40C1`). It prints message 17, "The screen shows a clock counting down. It shows ", the hours, ":", the minutes past the hour in two digits padded with 0, ".", the seconds and message 18, "." (`$40C4-$40F3`); minutes_to_hours (`$40F8`) divides the minutes by 60 through engine `api_divide` (`$0410`), which leaves the quotient in A and the remainder in `$D3`. So the clock reads 1:00.0 when armed and 0:59.45 a tick later. It returns the carry set, so the view is redrawn.
- `$4023` stop_random_encounters, action square 8: sets `$3A2F` to 0.

The header bytes lie in the map record. Engine `enter_map` writes the map back to the disk before it loads another (engine `$25C3`, `save_map` `$2856-$288F`, all 35 pages from `$3400`), so what the code writes stays with the map on later visits.
