# Map 13, Sleeper Base, level 2 — verified technical facts

Level 2 of Sleeper Base: its ladder reads "A ladder is here. 1) Climb up to lvl 1. 2) Remain on lvl 2. 3) Climb down to lvl 3." (message 60), and level 1's ladder offers "2) Climb down to lvl 2." (map 7's message 27). Its rooms include shelves of books, a sickbay ("The Doctor is in.", message 19), what was "once the chief Medical officer's office" (message 53), "the base's Nuclear Medicine facility" (message 55), a chemical synthesizer and four clone pods. It is 32 x 32 squares, stored on side 4 of the disks as 31 pages from T24/L17 (track 24, logical sector 17), entry 13 of the map directory at T35/L14 (engine `point_at_maps`, `$28CE`). Engine `enter_map` (`$25BD`) loads it to `$3400-$52FF` and unpacks its tile layer to `$DE00-$E1FF`. It is drawn with tile set 7 (tiles-7). Squares are given as (column, row). Every address here is this map's unless a part is named beside it.

## The map

- The class layer is `$3400-$35FF` and the number layer `$3600-$39FF`. The map record is at `$3A00`, since the map's byte in T35/L8 is not `$40` (engine `load_map_pages`, `$2606-$2616`).
- `$3A2C`, the size: 32 (engine `enter_map`, `$25D3`).
- `$3A30`, the tile set: 7 (engine `$25EE`).
- `$3A33`, the tile drawn off the map: 0 (engine `draw_square`, `$0B5E`).
- `$3A2F`, random encounters: 0, never (game `random_encounter`, `$B017`); `$3A31` and `$3A32` are 0 as well.
- `$3A34`/`$3A35`, the time a step takes: a quarter of a minute (fraction 64, minutes 0; game `advance_clock` `$AF32`).
- `$3A36`, ticks: 1 a step, added to `$D2` and to the elapsed count `$04-$06` (game `$AF58-$AF72`), so game `health_tick` (`$B795`) runs every 16th step (game `$AF75-$AF7B`).
- Squares, 1,024: 479 of class 0, 462 blocking squares (class 11), 35 message squares (1), 24 check squares (2), 8 loot bags (5), 7 exits (10), 5 question squares (8) and 4 action squares (6).
- Records, named by the class lists of header words 3-18 (`$3A06-$3A25`, engine `action_record` `$09B8`): 44 message squares, 21 loot bags, 16 check squares, 15 action squares, 13 question squares, 12 blocking squares, 10 exits, 10 remote changes and 3 tile squares.
- Text: messages 0-82, packed from `$4571` (header word 0, engine `select_map_text` `$1E4F`). No record, no header byte and none of the map's code names messages 20 ("Clone processing in progress."), 45 ("Unfortunately you were cut by some shards of crystal.") or 67.
- No monsters and nobody to hire. No square or change on the map is of class 3, the encounters, whose list word holds the tile squares' list (`$3C6D`), and random encounters never happen. Header words 1 and 2 (the monster names and records), 18 (the class-15 list) and 20 (the NPC list, `$3A28`) all hold `$4571`, the address of the text.

## Exits

Record byte 3 is the map an exit leads to (game `square_exit`, `$89A3`).

- To map 7, Sleeper Base, level 1, and map 15, level 3: exits 1 (`$4449`) and 2 (`$444E`), each to (1,30). No square holds them; the ladder at (1,28), question square 0 (`$439F`), makes them. Its question, message 60, is answered with one key: 1 makes the square exit 1, 2 changes nothing and 3 makes it exit 2. Each exit's change, `$FD`, trades the question back (engine `alter_square`, `$0A00`).
- The books and the sickbay: exit 5 (`$4459`) on (4,13), (5,13), (6,13), (1,20) and (2,20), "Shelves full of books stand before you." (message 4), and exit 6 (`$445F`) on (1,13) and (5,20), "The Doctor is in." (message 19), both asking first. Each leads to the party's own square (relative, +0,+0), and its change makes the square action square 4 (`$3D5B`) or 5 (`$3D8C`). Engine `enter_map` does nothing for the map in memory (engine `$25BF`) and the exit returns the carry set (game `$8A34`), so game `run_square_action` (`$ACC1`) runs the action square at once: `$82`, module 2, the library, named "   Books   ", or `$80`, module 0, the doctor, named "  Sickbay  ". Each change, `$FD`, trades the exit back.
- In the clone pods: exits 4 and 7-10 (`$4453`, `$4465-$4479`) move the party a few rows, relative to its square (below).
- Exit 13 (`$447A`) leads to (23,21), beside the synthesizer, but no square holds it and no change in the map's records, nor the map's code, names it.

## Its own code

The code list, header word 19 (`$3A26`), is at `$3DE0` and has three entries: 0 `$3DE6`, 1 `$424E`, 2 `$4325`. An action square whose record byte 0 is below `$80` runs entry n (game `run_action` `$8845`: engine `api_map_class_entry` `$0428` with Y = `$10` at game `$885E`, then game `jump_work_ptr` `$AC69`), entered with the carry clear (the ASL at engine `$09D5`). When the routine returns, a set carry has the view redrawn (game `$8872`); then the record's change at +1/+2 is applied to the party's square (game `$8840`, `alter_party_square` `$B105`), and a written change runs the new square at once (game `run_square_action`, `$ACC1`). All three routines return the carry clear.

- `$3DE6` incubate_clone, action squares 0-3: selects party position 1 (engine `api_select_member` `$0335` with A = 1) and copies its 256-byte record into clone slot n, `$3E3E` + 256 × n, n being record byte +3 (`$3DEB-$3E00`). In the copy it clears the 30 item pairs +`$BD`-+`$F8`, the weapon slot +`$1F`, the armour class +`$1A`, the armour slot +`$25` and the cash +`$15`-+`$17` (`$3E02-$3E21`). It then stamps the 32-bit elapsed count, `$04`, `$05`, `$06` and its top byte engine `elapsed_3` (`$F4FD`), into clone_times + 4 × n (`$3E23-$3E39`). The member stays in the party.
- `$3E3E` clone_slots: four 256-byte character records (clone_slot_1, clone_slot_2 and clone_slot_3 begin at `$3F3E`, `$403E` and `$413E`). `$423E` clone_times: four 4-byte stamps. All are 0 in the map as stored.
- `$424E` release_clone, action squares 11-14: n is record byte +3, which it stores in the operand at `$428C` (release_slot_op). It subtracts stamp n from the elapsed count, keeping bytes 1 and 3 of the difference in the operands at `$4279` (release_age_1) and `$4280` (release_age_3) (`$4258-$4273`), then subtracts `$2D` from the upper three bytes (`$4276-$4283`): the clone is ready once 11,520 ($2D00) ticks have passed. On this map a step adds 1 tick for a quarter of a minute, so that is 11,520 steps here, 48 hours of game time; battle rounds (game `$B393`) and V)iews that come round to their first party (game `$9BAE`) add to the count too, and on other maps each adds that map's +`$36`.
  - Too soon: it enters the BIT at `$42E6` at `$42E7`, a LDY #6, and copies record bytes +6/+7 into +1/+2.
  - When records_in_use (`$0A`) is 7 or more: it enters the BIT at `$42E3` at `$42E4`, a LDY #8, and copies +8/+9 (`$4285-$4289`).
  - Otherwise it copies slot n into character record `$0A` + 1 (engine `api_select_character` `$0338`, `$428B-$42A4`), adds one to `$0A` and to the party's size `$07`, and stores the record's number at position `$07` of the party table at (`$68`) (`$42A6-$42AE`). It prints clone_name_prompt (`$42FC`), "Enter new name for cloned player", reads a line of up to 13 characters (engine `api_input_line`, `$02EA`) into engine `sector_buffer` (`$5A00`), asks again after a cancel or an empty line (`$42CE-$42D5`), and copies the line's first 14 bytes over the record's name, +`$00`-+`$0D` (`$42D7-$42DF`). Then it copies +4/+5 into +1/+2 (`$42E1-$42F5`).
- `$4325` refill_loot_bag, action squares 6-10: copies loot bag +3 (kept in refill_from_bag, `$437D`) over loot bag +4 (refill_to_bag, `$437E`), each found through engine `api_map_class_entry` (`$0428`) with Y = 5 (`$4339-$434E`). It copies from byte +2, pair by pair, up to and including the `$FF` (`$4351-$4369`); a cash entry, `$5E` or `$DE`, ends the copy after its two bytes, with no `$FF` (`$436B-$4373`). No bag it copies here holds cash.
- The slots and stamps lie in the map's own pages. Engine `enter_map` writes the map back to the disk before it loads another (engine `$25C3`, `save_map` `$2856-$288F`, all 31 pages from `$3400`), so a clone keeps its slot and stamp while the party is away. Nothing in the map's code clears a slot or its stamp.

### The clone pods

The four pods stand side by side. In pod n (0-3), x is 20, 23, 26 or 29: its entrance is (x,28), its inside (x,29), its back (x,30), and its panel (x+1,27).

- The entrance is message square 1 (`$3AB6`), "Clone Pod." (message 26), which makes the square check square 5 (`$3BA5`, flags `$C0`): "The Clone Pod opens to accept you, though it looks a bit small inside." (message 28). Its one pair passes when the party's size is 1 (game `$8E85-$8E8A`). A single character is carried in ("The walkway scrolls forward and gently carries you inside the pod.", message 29) by exit 7 to (x,29); a larger party is put back on (x,27) by exit 8 with message 30, "The walkway scrolls back and deposits you outside the pod because it can only accept one person at a time.". Each exit's change, `$FD`, makes the entrance check square 5 again.
- Inside, check square 6 (`$3BB2`, flags `$C0`) wants Clone fluid (item 66) carried and uses a charge of it (game `$8E65-$8E70`). Without it, "You don't have the necessary chemicals to clone yourself." (message 22), and exit 10 moves the character back to (x,27). With it, "Proceed." (message 18) and remote change 0 (`$44E5`), which makes the entrance blocking square 1, "This pod is in use." (message 21), without a redraw, and the party's square exit 9, which moves the character on to the back and puts check square 6 back.
- The back, action square 7 + n (`$3DA4`, `$3DA9`, `$3DAE`, `$3DB3`), runs refill_loot_bag, which copies loot bag 18 (`$3D1E`, a Jug) over loot bag 0, 2, 3 or 4. Its change, remote change 15 + n (`$44F5`, `$4502`, `$450F`, `$451C`), makes the panel question square 12 + n, puts that loot bag on (x,27), and makes the party's square action square n (`$3D4B-$3D5A`), which runs incubate_clone for slot n at once. Action square n's change is exit 4 (`$4453`): "Clone incubation proceeding." (message 9), the character is moved to (x,26), and the back becomes tile square 2 (`$3C79`, tile 7).
- The panels at (21,27), (24,27), (27,27) and (30,27) start as question squares 1, 9, 10 and 11 (`$43AC`, `$43E7-$4404`), and a pod in use has question squares 12-15 (`$4405-$442C`). Both ask "Clone Pod control: 1) Abort clone incubation. 2) Release clone." (message 23).
  - 1 on either: message squares 35-38 show "Clone incubation aborted." (message 25) and lead to remote change 20 + n (`$4529`, `$453B`, `$454D`, `$455F`), which puts back the entrance (message square 1), the inside (check square 6) and the back (action square 7 + n) and makes the panel question square 1, 9, 10 or 11 again.
  - 2 on a panel that starts empty: "Clone pod is empty." (message square 7, message 24).
  - 2 on a pod in use: action square 11 + n (`$3DB8`, `$3DC2`, `$3DCC`, `$3DD6`) runs release_clone, whose three outcomes are the record's pairs at +4, +6 and +8. Released: message squares 39-42, "Clone released." (message 10), and the same remote change 20 + n. Too soon: "Clone incubation time is insufficient for release." (message 47, message squares 10, 12, 16 and 33). No room: "No room in roster for clone." (message 82, message squares 11, 15, 17 and 34). The last two put question square 12 + n back.

## Open

- `$42F9-$42FB`, three zero bytes between release_clone's RTS at `$42F8` and clone_name_prompt at `$42FC`: no word in the map's 64 KB snapshot equals `$42F9`, `$42FA` or `$42FB`, and no operand of the map's code reaches them. What they are for is not known.
- release_clone stores the clone's record number through `$68`/`$69` without setting that pointer. Engine `select_member` (`$11F7`), game `draw_other_parties` (`$AD13`) and game `party_at_square` (`$AFD6`) leave it on the current party's table; not every path from the last of those to the panel has been traced.
