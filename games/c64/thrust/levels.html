01 · The six caves

Six caves, each built from two walls

Each level is a shaft cut down into a planet. The rock on either side is a wall, and each wall is stored as a list of runs: so many rows going straight down, so many leaning left or right.

Drawn by this page from the listing's bytes: the walls by a port of the game's wall generators ($841C), the objects from the level's lists ($A1EE), each in its sprite and colour.

The walls are drawn on every second pixel line, as draw_walls ($828B) draws them, so the rock has the game's stripes. One step across is four pixels and one row down is two lines, the same scale the game uses on screen. The port is checked against the game's own generator code, run on the kit's 6502 for all six levels: test_levels.js, beside this page, compares 12,240 rows.

The yellow crosses mark the restart points ($A879): a ship lost below one comes back at the last point above where it was lost. Levels 4 to 6 each have a door that a switch opens. Door open draws it as move_doors ($917D) leaves it when fully open.

02 · What changes from level to level

Gravity grows with every level

Each level has its own gravity, colours, objects and restart points, read from tables indexed by the level number ($A6A4).

LevelGravityWall colourGun colourShield colourGunsFuel tanksSwitchesRestart points

Gravity from $A8F7, added to the ship's falling speed on 6 passes in 16. Colours from $A92D, $A945 and $A94B. Counts from each level's type list and $A873.

After level 6 the game starts again at level 1. The second time round gravity pulls upwards, the third time the walls are invisible, and the fourth time both. Gravity reversed is the same table negated. An invisible wall is drawn as usual, but the play area is shown through a colour screen ($5400) where the walls' colour is black, until the shield is raised.
