# Jet Set Willy — orientation

## Disk and power-on route

The contributor’s CMM D64 was recovered from repository history into private `work/game.d64`. Directory: `JET SET WILLY+` (126 blocks), `JET SET WIL.PIC` (15 blocks). Autostart the first file on a hard-reset PAL C64 in VICE MCP 3.13.1, explicitly resuming after reset/autostart if paused.

Wait for the animated CMMO intro. Hold fire on **control port 1** until its exit/fade starts, release, and wait for the trainer. Its live read at `$2AF7` requires `$DC01=$EF`; Space and port 2 fire did not dismiss it. Choose `N` for unlimited lives, `N` for the second option and `N` for the third (hold each for 60 frames, release for 30). After decompression the title appears; advance 600 frames and save `work/title.vsf` without ROMs. Hold Return for 60 frames, release, advance 120 frames. Confirm THE BATHROOM and save `work/play.vsf` without ROMs.

Take snapshots with `pause()` in `kit/c64/vice.py`, not a bare pause call. Frame batches must stay within the emulator tool’s accepted limits; wait for the named screens rather than assuming a timed loading batch completed.

## Why the listing uses play

The fresh title and play snapshots each match every one of the imported analysis’s 6,777 code-typed bytes and 514 word-typed bytes. Byte-typed differences from the old title capture: 104 at the newly booted title, 957 in play. No code bytes differ between fresh title and play; sprite slots `$4000–$6AFF` also agree. Room ranges differ at 16 bytes in `$B000–$CDFF` and 24 bytes in `$E000–$FDFF`, so room/session state is not assumed immutable.

The title IRQ vector is `$0314=$A801`; play installs `$0314=$33E1`. Thus play preserves the full imported code and authored sprite data while establishing the game’s own initialized handlers and room state. The Source listing uses `work/play.vsf`, with labels/types/comments seeded from the Ghidra export, inspected in regenerator2000 and exported through `symbols_export.py`. It is generated by `listing.py` alone.

## Scope and tools

This is one resident game load. The earlier crack intro and trainer are boot provenance. The imported models are unknown and are recorded in `game.json`; the original text export is private. Silver needs normal coverage/verification and a maintainer check.

VICE MCP 3.13.1 health check on 30 September 2026: 55/57 passed; `pause-at-instruction` and `unpaced-calls` failed. Use the pause workaround and paced calls. The emulator runs with sound disabled on a virtual X display. No headless VICE build is used because the kit reports broken CPU stopping there.

Rebuild the disassembler project with `symbols_import.py <game> work/play.vsf`, start it through `tools.py r2000`, export with `symbols_export.py`, then `listing.py <game> work/play.vsf`. Binaries, snapshots and projects remain private.

The final cold hand-over snapshot is `work/entry.vsf`, stopped at `$3C23` after answering all three trainer prompts with N. The RLE decoder jumps there at `$0140`; port `$37`, DDR `$2F`, CIA2 `$97` and `$D018=$15` were observed. It matches all 7,415 code-typed bytes of the play image. The retained copy routine under I/O can be executed in a controlled test, but its entry did not run on this CMM boot.
