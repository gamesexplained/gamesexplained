Every stage loads its own copy of the music, so the game holds 35 tunes in nine sets. Two of them, in the ending's file, are never played.

Music

Music: four tunes for every stage, three for the ending

Chris Hülsbeck and Ramiro Vaca are credited with the music and sound effects in the ending's own text. Each stage's first file brings a copy of the music driver and a block of music data with four tunes: the stage's theme, the boss music, the stage-end jingle and the game-over jingle. Pick a tune to hear the game's own driver play it.

The player runs the driver from each part's own file on the kit's 6502 simulator, starts a tune the way the game does ($637C with the data's address, then $6379 with the tune's number) and calls $6370 once a frame, as the raster interrupt at $0DE6 does. test_music.js runs the same calls on the listing's bytes and compares every write to the sound chip, frame by frame, for all 35 tunes. The filter is a model of one 6581 chip, and real chips differ.

The driver

One driver, copied into every stage

The driver sits at $6370-$6D3F in every stage's first file, byte for byte the same code, and the resident program reaches it only through five jumps at the start: $6370 plays one frame, $6373 silences the chip, $6376 asks for a sound effect, $6379 asks for a tune and $637C points the driver at its music data. The data follows at $6D40. The ending's file carries the same driver moved up by $490 bytes, to $6800, with its data at $71D0.

The data block starts with 22 offsets that music_data ($6564) turns into addresses. A tune is a column of the tune table: its start, loop and end positions, its tempo and the rows in each pattern. Each position names, for each of the three voices, a pattern, a transposition and an instrument. A pattern is a list of notes, each played through an instrument with its own pulse sweep, vibrato, detune and, on voice 1, a filter sweep (start_instrument, $6730).

The sound effects use the same tracks. Positions 0 to 22 of the third voice's track hold no tune at all: start_sound ($6544) plays the pattern at the effect's position on that voice in place of the music, so every explosion, shot and pick-up interrupts the melody's third voice for a moment. The resident program asks for them through play_sound ($33FB), which lets only some effects through when they come too fast.

The tune request keeps the X register as well as the tune's number, and the stage code and the resident program both set X before asking. start_tune loads that value at $64B9 and loads the tune's start position over it two instructions later, so X changes nothing.

The ending

Music: the ending plays one of its three tunes

The ending's music data holds three tunes. ending_start asks for tune 0 at $8025, and no other instruction in the file asks for a tune, so tunes 1 and 2 never play. Tune 2 is the longest piece in the game, 130 seconds before it repeats. Press "Ending · 2" in the player above to hear it.
