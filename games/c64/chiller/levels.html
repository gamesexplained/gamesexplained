02 · Behind the maps

How each screen is built and saved

Each of the ten screens has its own 128-byte settings record at $7000-$757F. setup_screen ($5E19) reads the fields below to build the play area, place the players and enemies, and set up the crosses. The first five levels keep their graphics at $8000-$B1FF, one $A00 block each; the way back borrows them.

The way home reuses the first five levels, but keeps the changes you made on the way out. When the boy moves on, next_screen ($7680) saves screen rows 1 to 24. The forest goes to $7800. The other four are stored in RAM hidden under the KERNAL ROM, at $E000, $E400, $E800 and $EC00. Writing there works with the ROM switched in; reading the saved screen back requires copy_under_kernal ($72A4) to set processor port $01 to $34 temporarily.

The first five settings records list five blue crosses each. The return records list ten, so place_crosses adds five red crosses to each saved screen as it is set up. The maps above use the untouched outward layouts in place of saved screens and show where both sets of crosses begin.

03 · Enemy paths

How the enemies move

Choose a screen and enemy, then use Step or Run to follow its path. The enemy uses its own sprite frames; the route is scaled for clarity, not shown at game speed.

path_step $CC12 moves an enemy a pixel at a time and reads the next byte from path_scripts $4A00-$4A8F every eighth move: 0 up, 1 down, 2 left, 3 right, and $FF loops back. Each press of Step advances one direction byte. The arrow shows the next direction.
