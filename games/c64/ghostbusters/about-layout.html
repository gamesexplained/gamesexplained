About this page

The copies studied

The pages describe the game's own code and data: Activision's program, which starts at $6000, and everything it builds. The addresses are those of the copy analysed, a single file that holds the whole of memory from $0314 up so the game loads in one go.

A second copy, a cracked disk whose one file unpacks itself and then jumps to $6000, was run in the emulator to that point and compared byte for byte. Every byte of the game's code and data is the same at the same address, with three kinds of exception:

  • Values the game changes as it runs. At least one copy was saved from memory after the game had run. Nineteen bytes of the speech player that it rewrites while it talks differ, as does one operand at $8000, and the flag at $6328 that says a name has been typed: it is set in the disk copy, so there F3 on the title skips the interview from the first game.
  • Two car pictures. The disk copy has other bytes at $0400-$07FF, where the compact's and the hearse's pictures are kept. Bought in that copy, both cars show as noise; the station wagon and the high-performance car are intact.
  • Part of the laugh. The 32 bytes at $FD30-$FD4F hold, in the disk copy, the KERNAL's table of vectors in place of speech data. Played through the port of the speech player, phrase 3 then differs in 750 of its 17,768 writes; the other phrases are unchanged.

The one-file copy is intact in all three places, which is why it is the one analysed. Its own additions, left out of the other tabs, are these:

  • The hand-over. The file's first two bytes overwrite the interrupt vector, so the first interrupt after loading runs a short routine at $C800. It puts back pages $0200 and $0300 and jumps to $6000, the game's cold start. Loaded through the disk drive with interrupts running, the vector arrives before the code it points to and the machine falls back to READY, so it needs a loader that writes memory in one go.
  • A turbo tape loader that nothing calls, at $CE00. It points the RESTORE key's interrupt at $CEC1, which would fill memory with $02, an opcode that stops the processor. A chain at $CF80, also never reached, loads and runs $0A00 and then $0E00; in this file those addresses hold car graphics. That these are the original tape's loading sequence is an inference.
  • Leftover memory: the power-on pattern in unused RAM, and the bytes at $4000-$5FFF, which the start-up clears and rebuilds.
