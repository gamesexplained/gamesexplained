# Title and score display — technical facts

The disk file `9%` expands to `$6C00-$B937`. A stopping execution checkpoint captured the original loader's return at `$7FF5`, before title initialization. That entry selects the post-game score display; the separate cold title entry is `$8009`. The listing explains all 19768 loaded bytes, including 6830 code bytes. Upper display memory is cleared, copied or generated by this program and is named separately rather than counted again as authored input.

## Presentation and graphics

The top title bitmap has forty columns by thirteen eight-by-eight cells: 4160 bitmap bytes and two 520-byte attribute allocations. Initialization copies them into the selected VIC bitmap/screen/colour locations. It also copies five sixty-four-byte decorative sprite shapes and a transposed sixty-four-glyph font. The latter stores each of sixteen bitmap rows as sixty-four consecutive character values. Rendering the transposed source confirmed letters at codes one through twenty-six, space $20, digits $30-$39 and the expected punctuation, including comma $2C, period $2E and colon $3A.

Raster callbacks reveal the display through a control-history wave, separation of two leading sprites, shared-colour changes and a five-step panel fill. Later callbacks alternate two bitmap buffers, shift thirty-two forty-eight-byte columns and draw thirty-two text characters through the transposed font. Seven panel thresholds select colour pairs and transition clearing. Six decorative sprites have independent shape phases and X movement.

The foreground follows a short JMP cycle while interrupts animate and handle input. Alternate routines at `$908D/$90CF/$912A/$9199` produce SID/register/border patterns and rewrite two vector-like words. Their intended trigger remains open; they are not presented as a player-facing feature.

## Encoded credits

The reader's trampoline is `$8793` to `$B935`, then an indirect JMP through `$ADB6` to `$8E08`. Its decoded byte is `((stored XOR xor_key) - additive_key) & 255`. The additive key advances by $4D and the XOR key decreases by $9A. Their initial values are $12/$5C. The instruction path, including the return-stack handling through `$80DC`, was traced on the original first credit read (`work/trace_title_encrypted_reader.json`).

The `$B758-$B934` stream decodes to the program, graphics, music, effects, intro, music-driver, loading-system, protection and production credits. Zero starts a new thirty-two-character row, $FE supplies a horizontal advance and $FF ends the stream. Output characters are masked to six bits. Each encoded row is described individually in the listing. The decoded credits name Manfred Trenz, Andreas Escher, Markus Siebold, Stefan Albes, Dave Hogendorf, Edwin Determann, Markus Wiederstein, Joerg Prenzing, Julian Eggebrecht and Marc A. Ullrich in their respective roles.

## Starting counters and score entry

Fire starts a fade and countdown before entering the resident engine through the word at `$AF53`. The counter setup reads byte `$B3B8`, value one, writes it to the continue byte `$DBFF`, and computes the lives byte as twice that value plus one. A read watchpoint and instruction steps confirmed writes one and three (`work/trace_title_initial_counters.json`). The source byte lies among retained utility/BASIC-data bytes; it is not assumed to be a user-editable setting.

The score display formats four packed-BCD bytes as seven digits and the level index as two displayed characters. A lexicographic comparison against ten entries accepts equality. Insertion shifts lower-ranked twenty-five-byte records and stores seven score digits, sixteen name characters and two level characters. Name editing handles cursor blink, repeat delay, Delete, Return and a fire-button default name.

Saving calls the resident raw-sector writer for one 256-byte block beginning at `$67FF`, with track eighteen and sector eighteen. The score table starts at `$6800`. This is a sector operation, not a file named by the two parameter bytes. The save result's carry flag selects the failure message.

## Retained utility fragments

The bytes `$B358-$B757` contain retained fragments of another program, interspersed with data and zeros. Their absolute calls and self-modifying operand addresses match original addresses $14A8 above the stored copy: for example, the page-copy fragment at `$B658` resolves at `$CB00`, with its operand writes to `$CB13/$CB16`. They remain data in the title listing because execution at their stored addresses is not established. The title does directly use the first retained data byte at `$B3B8`, as traced above.

## Music and open questions

Two stored songs have thirty patterns, fourteen instruments and twenty arpeggio selectors. Initialization selects song zero for the title and song one for score entry. The music core pairs all 816 instructions with the flight driver; its one immediate change makes the voice loop emit voices two, one and zero. All relocated data references were reviewed.

The alternate pattern routines' trigger and the separate use of forty-one bytes after the bitmap source remain open. No optional playthrough or combined-mechanics replay was recorded.
