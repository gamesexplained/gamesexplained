Alter Ego

01 · Disk addressing

Finding a scene on disk

Scene data is a logical stream, but the disk reader receives fixed-size records. Only 252 bytes of each live record belong to that stream. Moving one logical byte across a boundary skips the surrounding transport fields.

The mapping at $5C3D uses record = floor(offset/252), cursor = offset % 252 + 3. The cursor is a zero-based position in the live 256-byte buffer.

02 · Inside the game

A life in 380 bytes

A saved life joins seven separate regions of memory. Most of its space belongs to the state vector and Life Map. The player’s name and the small progress fields travel with them.

Three record lengths with different meanings

The disk-stream payload has 252 bytes. The retained host REL record has 254, including two framing bytes. The live buffer has 256, adding status and an identifier. None of these lengths is the 380-byte save payload.

03 · Inside the game

A virtual machine inside the program

Much of the program runs as virtual-machine procedures, with gateways into native 6510 code. The gateway at $6FF4 reads an inline target address. The gateway at $7059 reads a different header: workspace size and a signed stack adjustment, followed by the native body.

Why an inline header matters

A byte following a call can belong to the called routine’s argument record rather than to the instruction stream. The imported annotations preserve those boundaries instead of disassembling every byte as a CPU instruction.

05 · Inside the game

A dictionary for scene text

The grouped LZW decoder builds dictionary entries while expanding a scene. Its prefix table holds two bytes per entry; its suffix table holds the final byte. The first 256 entries represent literal bytes, and generated entries occupy the remaining slots.
