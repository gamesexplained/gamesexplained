# Load 10 — verified technical facts

The resident draw loop at `$6D41–$6D63` ran 200 iterations in the first 200 frames after this forced load returned. Its four indexed reads use `$81CF`, `$82CF`, `$83CF` and `$84CF` to place a metatile's four character codes in a two-by-two block. The resident movement checks use the indexed attribute table at `$80CF`; the exact meanings of all its bit combinations remain open. This observation follows a forced transition and does not establish a route by ordinary play.

The entry snapshot has 14 row pointers in split tables at `$85CF` and `$8620`. They point to rows beginning at `$8671` and spaced 48 bytes apart; the address immediately after that storage is `$8911`, the character-data pointer recorded at `$7F41`. The downward scroll check uses `$7F4C` as its vertical boundary. This does not establish that every stored cell is encountered during play.

The captured sound pointers select voice lists at $9D7B, $9D7F, $9D83; their records name 3 distinct event patterns. In the captured selector-1 loop, the resident sequencer selected each pattern and reached its documented zero marker in the listing-based simulator. `test_stage_sound_patterns.js` checks the pointers, pattern boundaries and those visits. This observation does not establish when ordinary play selects the sound.

The captured descriptor names 1 six-byte trigger records at `$8F1A` and 1 sixteen-byte stage object records at `$8F20`. `$7979` copies the trigger fields; `$4655` returns before reading the object pointer if its count is zero, otherwise it copies the fields and calls the map updater. `test_stage_records.js` checks the copies and descriptions, stubbing the map updater for the sixteen-byte records. These captured records do not establish that ordinary play activates them.

In the forced play capture, 2 stable 63-byte sprite bitmaps from this load were named by active display-slot entries in VIC bank 3. Their entry and play bytes match; non-stopping checkpoints saw no instruction entry into those bitmap ranges during the following 200 frames. The observation covers those captured states and does not establish all animation or ordinary-play behavior.

The loaded pointer at `$7F3F/$7F40` targets `$8EF9`, inside the eight-page character-copy source at `$8911`. The entry was observed in the 200-frame forced-play probe and monitor collection. The code and graphics uses overlap; `codemap.json` records only observed instruction starts in that source whose bytes still matched the load-entry snapshot.

Sampling the forced play capture every ten frames through frame 200 found 4 additional active sprite pointers in this load. Their bitmap bytes matched the entry snapshot at their first sampled frame, and execution checkpoints recorded no instruction entries in those ranges during the same 200-frame probe. The recorded display settings and first sampled frame are in `display-observations.json`; natural reachability remains open.

The supplied side A file with index $0A supplies two compressed streams. Executing the game’s decoder on those bytes in the 6502 simulator consumed 652 and 4789 bytes and wrote $EB40–$F43F and $7EDF–$A23E, respectively. The decoded output differed from the forced VICE load-entry snapshot at $9FEB–$9FED; the resident selector-10 patch at $2A90 makes all output bytes match. The extracted file has 147 further bytes after the two streams; their role is not established. This establishes these stream writes for the supplied image, not natural reachability or ownership of repeated data across loads.

Controlled record-copy, frame-restore and display-routine simulations selected 2 additional bitmap pointers in this load. Slot assignment, position, effect state and one colour were forced. The bitmaps match the load-entry and play captures; no instruction entered their ranges during a 200-frame probe. These examples do not establish natural reachability.

The load’s type-$0C entity vector selects a dispatcher at $9F02. Its four captured state-table pairs point to $9F1C, $9F40, $9F59, $9F77; the state byte is not locally bounded. Listing tests check all four dispatches in each load; seven controlled VICE calls check all four in load 8 and one each in the other loads. The state index and ordinary-play reachability remain open.

Type-$0C states 0, 1 and 2 at $9F1C, $9F40 and $9F59 call an event helper and, if it returns, increment a counter, count down a field or count it back up. State 0 selects state 1 at counter 10, state 1 selects state 2 when the field is negative, and state 2 returns to state 0 when the field equals its saved target. Listing tests and nine controlled VICE calls check these branches across four loads with callbacks stubbed and decimal mode clear; natural reachability remains open.

Type-$0C state 3 at $9F77 uses $1AC2,X as a positive countdown or a negative phase and chooses a callback from the sign of $9FE0. The event helper at $9FB1 can select state 3 and remove its own return address so that it skips the rest of the calling handler. Listing tests and eleven controlled VICE calls cover the state and both stack paths in four loads with external callbacks stubbed; natural reachability remains open.
