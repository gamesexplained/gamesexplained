1989 · Taito America

Qix

The C64 Qix reads both joystick ports at once and treats them as one stick, so either port plays. It reads one key, RUN/STOP, to pause. Push both sticks the same way and they cancel each other out.

01 · What the game reads

One routine reads both ports as one stick, once a frame

Press the buttons below to hold a direction or fire on either stick. The page runs the game's own stick routine on what you hold and shows what the game makes of it.

Port 1

Port 2

The game's read_stick ($83DF), running in this page on the kit's 6502, over the game's bytes from the listing. It runs once each time you press a button, as the play interrupt runs it once a frame, and it keeps the last straight direction from one run to the next, as the game does.

Once a frame the play interrupt calls read_stick. The routine reads the two joystick ports, $DC00 for port 2 and $DC01 for port 1, and combines them with an exclusive OR. A port's line reads 0 while its stick holds that direction or fire, and 1 otherwise, so the combined bit is 1 when exactly one of the two sticks holds it. The routine keeps the five bits for up, down, left, right and fire in $2E, where the rest of the game picks them up.

The game never asks which port the stick is in. Every read of the sticks in the program combines the two ports this way: the menu's ($821C), the pause's, the wait for fire at the end of a level ($163F) and the drive-error screen's ($1C66). So a player can choose 1 PLAYER, 2 PLAYER or PRACTICE with a stick in either port, and in a two-player game both players can share one stick.

02 · Two sticks

Secret: two sticks pushed the same way cancel each other out

With a stick in each port, pushing both the same way does nothing, and pressing both fire buttons does nothing.

The exclusive OR that lets either port play has a side effect. When both sticks hold the same direction, both lines read 0, and 0 combined with 0 is 0: the game sees nothing held. Hold up on both sticks in the panel above and $2E stays clear. The same goes for fire, so a slow draw started on one stick turns fast the moment the other stick's fire button is pressed too. Two sticks pushed in different directions combine instead, as if one stick were pushed both ways: up on one and left on the other is a diagonal (section 03).

A player with one stick never meets this. It matters in a two-player game played with two sticks plugged in, where the waiting player's stick is still read while the other player plays.

03 · Diagonals

A diagonal keeps the marker going the way it was going

The marker moves only up, down, left and right. When the stick is pushed diagonally, the game uses the last straight direction instead.

read_stick checks the four directions it reads for the four diagonals. On a diagonal it throws the directions away and puts back the last straight direction it saw, which it keeps at $840C, with the fire button as it is. Then it stores that direction as the last one again. So a marker going up keeps going up while the stick rolls to up and left, and turns left only when the stick reaches left. A diagonal pushed from rest moves nothing at all, because the last direction kept is no direction. Try it in the panel: hold up, then add left, then let go of up.

This keeps the marker on the pixel grid of the field: the edges, and every line the player draws, run straight across or straight down, and the code that follows them handles one direction at a time.

What the stick and fire do in each part of the game. The marker's movement and drawing code reads $2E; a slow draw skips the marker's step on every other pass ($991C). How it works explains the scoring.

Speed and points are decided separately. The marker's speed follows the fire button step by step (draw_step, $991C). The points follow the fire button at one moment only: draw_advance stores it at every step of the marker ($99BF), and when the line reaches the edge, the game reads the last one stored ($9994). A line with fire held on its last step counts as slow and scores double.

05 · The keyboard

RUN/STOP pauses, and RESTORE does nothing

The only key the game reads is RUN/STOP. Every frame, before it reads the stick, the play interrupt calls pause_check ($81D9), which selects the keyboard's row 7 on its own and reads it until two reads agree (read_runstop, $81A7). When RUN/STOP is down, the game silences the SID, stops its interrupts and waits for the key to be let go. Then it waits for either joystick port to change and goes back to the game. A key cannot end the pause, and neither can both sticks pushed the same way, for the reason in section 02.

RESTORE is wired to the processor's non-maskable interrupt, which the game points at a bare return from interrupt, so the key does nothing. There are no keys for music, restart or quitting: the game ends only when the last life is lost, and then it loads itself again from disk (Discoveries).
