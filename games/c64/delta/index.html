Commodore 64 · 1987 · Thalamus

Delta

Stavros Fasoulas drew every bullet in Delta as a letter of an inverted font, and the game finds out who was hit by reading the screen. Rob Hubbard wrote thirteen tunes for it, and the game asks for three.

01 · The play screen

One frame, rebuilt from memory

The picture below is drawn by this page from the game's memory and the video chip's registers, recorded over one frame of stage 2.

    Rebuilt with the site's C64 renderer from a frame recorded in VICE: memory as the frame began and every write to the video chip and the sprite pointers, with the raster line it happened on. Compared with VICE's own picture of the same frame, 0 pixels differ. The writes listed under the button are the recording's own.

    The C64 has eight sprites, and this screen shows far more than eight things that move: two rows of rocks, the enemies, the score panel at the top and eight icons along the bottom. The game reuses the same eight sprites five times a frame. A chain of raster interrupts ($1800, with the next handler's address kept at $1000) wakes up at chosen lines down the screen and moves the sprites, with new shapes and colours, to the next strip before the beam gets there. The main program does almost nothing: main_loop at $17C9 waits for line 228 and runs the sound.

    The play area itself is text. The stars, the enemies' fire and all of the player's weapons are characters on the screen at $4400, in a character set of only 64 glyphs at $4800.

    02 · Rob Hubbard's score

    Music: thirteen tunes, three in use

    The game carries a complete Hubbard music driver with thirteen tunes. Only three are ever requested.

    The game's own driver, run in the page. The buttons start each tune through set_tune at $C357, and every frame calls music_play at $BDE4, both executed by a small 6502 interpreter over the bytes $BC00-$CFFF as the game loads them. Checked against the same code run in the kit's 6502 simulator: every SID register write matched for every tune (9,000 frames for tunes 0, 11 and 12, 1,500 for the rest). The filter is one chip's: a 6581's cutoff curve. The drums' lowest notes sit under 100 Hz, which laptop and phone speakers barely play.

    The game asks for a tune by writing its number plus one into $117D, and the sound routine at $9D60 passes it on once a frame. Tune 11 starts with the title screen (a direct call at $17C3) and comes back at game over and name entry. Tune 12 plays when all 32 stages are cleared (game_completed, $9D00). Tune 0 is the in-game music, requested whenever play starts and at each player's turn.

    By default the player never hears tune 0. In play, the game uses the SID for its sound effects ($0FFD = 1). Pressing F5 on the title swaps the effects for the music, and then the request for tune 0 starts it. With the effects on, the same request only hands the three voices back to the effect player at $0406.

    Tunes 1 to 10 are short pieces of a few seconds that end on their own. They sit in the tune table at $C4F4 with the rest, and nothing in the game asks for them.

    03 · Colour from nothing

    An inverted character set

    Every set bit in Delta's font is drawn black. The colours come from the bits that are clear.

    Left: the three star glyphs, $2F, $30 and $31, as the frame is drawn: each is solid but for one clear pixel. Right: the 18 star positions at $100A-$101B, each drawn in all four quarters of the screen, run by a port of stars_update ($1DB9). Checked against the game's code in the kit's 6502 simulator over 600 frames. Colours are the three backgrounds of the recorded frame.

    The screen runs in the VIC-II's extended background colour mode ($D011 = $5C). In that mode only 64 glyphs exist, and the top two bits of each character code pick one of four background colours, $D021 to $D024, instead of choosing a glyph. Colour RAM is black everywhere (clear_screen, $0DDD). A set bit is therefore black, and a clear bit shows the background colour the code selects. The blank character $2E is solid, so empty space is black.

    A star is one character with a single clear bit. Three layers use the same trick with three codes: $6F, $30 and $B1 point at glyphs $2F, $30 and $31 through three different backgrounds, so each layer has its own colour. To move a layer, the game rotates the one row of its glyph that holds the clear bit (ROL at $1D1C). Every star of that layer slides one pixel left at once. When the bit falls out, it goes back in at the right edge and the six stars of the layer move one column left. The fast layer rotates twice a frame, the middle once, the slow one every second frame. The four background colours step through a six-entry cycle every fourth frame (colour_cycle_step, $1DDD), so the stars change colour as they drift.

    04 · Bullets made of type

    Every shot is a character

    The enemies' shots are cut out of whatever glyph lies under them, and hits are found by reading the screen.

    Position in the cell
    Underneath

    A port of draw_enemy_shot_0 ($25D5): the two glyphs under the shot are ANDed with two columns of the mask table shot_masks at $FF70. Checked against the game's code in the kit's 6502 simulator in 40 cases. Clear bits are drawn in one colour here; on the screen they take the background colour of the shot's character code.

    Enemy shots, homing bombs and eight-way bullets are all drawn with characters. An aimed shot is a four-pixel ball that moves one pixel at a time across two cells. The game does not draw the ball. It builds two new glyphs each frame, taking the glyphs under the shot and clearing the ball's bits out of them with one of eight masks. In an inverted font a clear bit is colour, so the ball appears, and a star under it stays visible. The bombs read the same table through patched operands ($28C1, $299C).

    Hits by reading the screen

    The VIC-II can report when a sprite touches a character ($D01F). Delta never reads that register. Instead:

    • an enemy is hit when one of the four cells under its sprite holds a glyph from $32 to $3F, the player's weapons. The low four bits of the glyph say which weapon hit it, and that shot is used up, except the orbiter's (enemies_hit_by_weapons, $2B0A);
    • the ship is hit when the cell under its middle holds a glyph below $2E, the enemies' fire (ship_hit_by_fire, $2BBC).

    Sprite against sprite (the ship and the enemies, the rows of rocks, the shop's icons) uses the chip's own collision register $D01E, read in three of the bands.

    05 · The corner shop in space

    The shop

    Some attack waves are made of weapon icons. Fly into a blue one to buy it. Grey ones kill.

    Credits
    Click an icon to fly into it.

    A port of shop_try_buy ($2261), checked against the game's code in the kit's 6502 simulator over all 280 combinations of icon, credits and shop state. Icon 4 bought with 7 credits, and icon 5 touched with 2, were also tried live in VICE.

    The shop is not a separate screen. It is an attack group like the others (bit 4 of the wave record's byte 2 marks it), whose sprites are the seven weapon icons, flying through the play area. In stage 1 it is the second group to arrive, about three seconds in. An icon costs its own number in credits. Icons the player can afford are light blue and the rest grey (icons_update, $0808).

    Touching an icon that costs more than the credits counts as being shot, and so does touching a second icon in the same shop: one purchase per visit. Buying spends every credit. The price goes, and each credit left over is paid out as 100 points. The bought icon then blinks 14 times along the bottom row, eight frames each, and only then takes effect.

    A credit comes from clearing a whole attack group: when a group ends and none of its enemies escaped, most groups add one ($80B5).

    06 · Thirty-two stages

    32 stages, and the difficulty stops rising at 16

    Each of the 32 stages announces itself in three words, and the ones you are entering bring rows of scenery along the top and bottom.

    Pass through the game

    Drawn from the game's tables: the three words from stage_banner_table ($F880) and stage_words ($EB80), in the game's font at $FC60; the scenery rows from stage_hazard_table ($F900); the fire rules from difficulty_by_loop ($FA20). The decoder was checked against all 32 banners read from the game; stage 2's banner was also brought up live in VICE. Colours as in reference/stage2-banner.png, which the drawing matches pixel for pixel. Stages with an orange edge have scenery rows.

    A banner is three of 30 eight-letter words, picked by two bytes per stage: the high four bits of the first byte choose the first word, the low four bits plus 4 the second, and the second byte plus 17 the third. The word list holds two that no stage uses: LOST and DRAGONS.

    The font has 39 glyphs of 20 bytes, ten rows of twelve pixels in multicolour, and the banner is drawn into eight sprites two letters at a time (banner_draw_step, $3B80).

    Difficulty depends on two numbers: the stage and the number of times the player has finished the game. Each enemy fires when its counter reaches the fire rate, and new fire is allowed only while the fire already in flight costs less than the budget (a shot counts 5, a bomb 10, a bullet 1). Both stop changing at stage 16 (fire_rate_set takes the stage capped at 15). After stage 32 the game plays tune 12, shows DELTA MISSION COMPLETE and starts again at stage 1 with the next of three tables (difficulty_set, $9D35).

    07 · The enemies

    Attack waves

    Up to seven enemies at once, each following a path of straight segments, with hit points and sometimes a second form.

    Each stage is a list of groups ($B800 for stages 1 to 21, $B900 after), and each group points at an eight-byte record in wave_records at $AB00. enemy_spawn ($811F) decodes it: hit points, animation, colour, which side to enter from, points, path, starting height and delay. One enemy enters per frame into a free sprite, up to seven.

    A path ($B500) is a list of segments ($A880), and each segment runs a list of (dx, dy) steps from $B000 for so many frames a step, mirrored as the record says (enemy_move_1, $82CC, and six copies, one per sprite). An enemy that leaves the play area is gone, and a group with an escapee earns no credit.

    Hit points come from $A100. An enemy with 0 or 1 dies at the first hit, and one with $FF cannot be destroyed. When a segment says so, an enemy whose hits run out changes into a new form instead of dying. In waves led by an indestructible enemy in the first sprite, destroying the one in the last sprite blows up the whole wave (enemies_wave_timers, $9024).

    Enemies are worth 5, 7, 10, 15, 20, 25, 50 or 100, and the panel shows ten times that: the score is kept in five digits and printed with a 0 after them. An extra life comes each time the panel's ten-thousands digit goes up (extra_life_check, $9CD6), so every 10,000 points, up to nine lives.

    09 · Left in the code

    Secret: a trainer nothing calls

    At $BA00 sits a routine that no instruction reaches. It was written to run in place of the jump to the ship's movement: holding F3 sets the lives back to 3, and F5 toggles two patches, one making the enemies' fire harmless ($2BC9) and one switching off the collision with the shop's icons ($2BDA). It ends by jumping to the ship's movement, so hooking it in would be a single changed address. It is probably the developer's own cheat for testing, left in the finished game.

    10 · A store one page off

    Bug: a timer cleared one page too low

    The wave routine at $9024 keeps a wave timer at $129E. At $9057 it clears a timer with STY $029E, one page below, an address nothing else reads or writes. The neighbouring code uses $129E throughout, so the store was almost certainly meant for it: the timer is not cleared there. The next instruction writes $129F, which nothing reads either.

    11 · Randomness

    Secret: the random numbers are the game's own code

    Delta has no random number generator. When it needs a random choice for the enemies' fire or the boss's aim, enemy_ai_step ($99AC) walks through the bytes at $3000, using each one to find the next. Those bytes are the game's own code: the routines that move the enemies' bullets and shots. Any change to that code would change how the enemies fire.

    12 · Leftovers

    Secret: 1986 and a disk command in memory

    • The title texts stored in the game say "(c)MCMLXXXVI" and "(c)1986 THALAMUS" ($F7B0). The title screen the player sees is a picture saying MCMLXXXVII and 1987.
    • $9FF4 holds the text S:DEMO DELTA, a disk-drive command to delete a file called DEMO DELTA, left in memory by the developer's tools.
    • Code no instruction reaches: $175E (switches the ROMs back in and restarts BASIC), $3D13, and a test of a stage flag at $9D77 padded out with sixteen NOPs.
