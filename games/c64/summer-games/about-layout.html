About this page

The copy studied

The pages describe Epyx's disk of 1984 as a PAL G64 image, its directory named SUMMER GAMES with the ID XX. Three images were supplied: two PAL images that agree on every file, and an NTSC image that boots through a different loader. The boot program loads SGLOAD, which draws the title screen and puts a fast loader in memory, then loads the engine, file B. The engine stays in memory to the end, with the players, the records, the menus, and the music, and loads the other parts by a one-letter name (module_letters): the opening ceremony and menus' pictures, file A, and the six event files, D for the pole vault, E for diving, F for the races, H for gymnastics, I for swimming, and K for skeet. Each is packed on the disk and unpacked as it loads (load_module). Each of those eight loads has its own listing on the Source tab, built from memory saved while it was running.

The world records are kept in file WR, which the game writes back after a new record, and file DEFAULT holds the records the disk was sold with, loaded only when WR cannot be read. Files L and M are never loaded (Discoveries). A few sectors belong to no file, and the copy protection reads one sector that is made to fail (Discoveries). Nothing on the disk suggests a crack or a trainer.

Original game credits

The title screen names seven designers: Scott Nelson, Erin Murphy, Stephen Mudry, Brian McGhie, Stephen Landrum, Jon Leupp, and Randy Glover. Other sources credit Stephen Landrum with the programming, Erin Murphy with the graphics, and Randy Glover with the music.347 Epyx published it in 1984; in Britain it came from Quicksilva and then U.S. Gold.2

Memory footprint

Every byte of the C64's 64 KB, one pixel each, 512 to a row. Lit pixels are code, graphics, sound, text, tables and variables; dim areas are screen and working memory.
