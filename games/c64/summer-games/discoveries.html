Commodore 64 · 1984 · Epyx

Summer Games: discoveries

A designer's name under every player's, a copyright the game never prints, a tune the ceremony keeps silent, a screen left on the disk unused, two scoring quirks, and a copy protection that stops the processor dead.

01 · Registration

Secret: B.B.MCGHIE picks a country

When each player has typed a name, the engine asks them to choose a flag with a line of 40 characters it keeps ready in memory: "B.B.MCGHIE PICK YOUR COUNTRY" (country_prompt). The first ten characters are a space for the player's name, and the engine writes the name over them before the line reaches the screen. Each player sees their own name before "PICK YOUR COUNTRY", and the name that filled the space while the program was written stays hidden in memory. Brian McGhie is one of the seven designers on the title screen (The people behind the game).

02 · The opening ceremony

Secret: a copyright of 1983

The ceremony's file ends with two lines of text that the ceremony never prints: "SUMMER GAMES" in reversed letters, and "COPYRIGHT (C) 1983 EPYX" (cer_copyright). The title screen, drawn by the boot loader before the ceremony loads, gives the year as 1984. The ceremony was finished, or at least begun, the year before the game came out.

03 · The opening ceremony

Secret: a second tune the ceremony never plays

The ceremony carries its own small music player, separate from the engine's, with a table of two tunes (cer_tunes). The second is the fanfare that plays as the torch-bearer climbs the steps. The first is never started: the ceremony only ever asks for tune 2 (start_tune). Its notes are the same as the engine's tune for the world records screen (tune_unused, tune_records), so the ceremony was probably once meant to end with it. Both can be heard on the Gameplay tab: the unused one is the second tune in the ceremony's player.

04 · The disk

Secret: an unused screen, and a copy of it

The engine loads each part of the game by a one-letter name, from a table of twelve letters (module_letters). The twelfth letter is L, and the disk has a file L: a packed character screen meant for $C400-$CC07. The menus only ever run modules 0 to 10, so module 11 stays on the disk, and what it was for is unknown. Beside it is file M, the same screen in other colours, whose letter is not in the table at all. The disk holds a few stray sectors that no file owns as well (About).

Inside file I, the swimming events, is a disk command: "N:SUMMER GAMES,SL", the drive's instruction to format a disk named SUMMER GAMES with the ID SL. It sits in bytes the event overwrites with its own data as it starts, so the command was never part of the program; it was left in the memory of the machine the file was saved from. The finished disk is named SUMMER GAMES, with the ID XX.

05 · Gymnastics

Quirk: a failed lean costs less than a fall

A vault that lands leaning forward or back costs a tenth of a point, and the gymnast then has 31 frames to push the stick against the lean and stand up (land_lean_fwd, land_lean_back). If the stick stays still, the program gives back 1.5 points ($475B) and then joins the fall, which takes 3.0 off ($4823, crash). The lean that is not recovered costs 1.6 in all, little more than half of a plain fall. The 1.5 looks like a refund meant to soften the fall after a lean, but it makes the lean's fall the cheaper of the two.

06 · Platform diving

Quirk: every bent entry scores zero

The judges mark a dive mostly on its entry into the water. The program looks up the diver's shape at the moment of entry in a table of base scores (entry_base): a straight body scores 100 when it is upright, 80 a frame off, 32 two frames off, and 0 flat. Every tuck, pike, and half-pike scores 0, whatever its angle. A diver who is still curled up at the water gets the same entry as a belly flop, so every dive must end in the layout, stick up, however it began (Gameplay).

07 · Every event

Secret: a protection that stops the processor

Before each event loads, the engine checks the disk. It asks the drive to read track 35, sector 1, with the command "U1: 5 0 35 1", and reads the drive's error channel; on the original disk that sector is made to fail, and the answer must be error 29. It tries six times (protection_check). A copy that passes the read, or fails it the wrong way, is sent to an instruction the 6502 was never given: the byte $02, which locks the processor until the machine is reset (jam). The machine shows no message and no crash screen: the picture stays as it was, and the stick and the keys go unanswered (run_event).

08 · Platform diving

Secret: the high and low judges are made up

Seven judges hold up cards after every dive, and the rules drop the highest and the lowest before the rest are added. In the code there is only one mark, the entry's score, and the five middle judges are that mark divided by five, in half points, with a few half points then moved at random from one judge to another (split_judges). The high judge is a copy of one of them plus nothing or a half, the low judge a copy of another less nothing or a half, and the seven are shuffled before the cards go up (high_low, shuffle_scores). The two cards the rules throw away are the only ones the program invents, so they never change the result (Gameplay).

09 · The races

Quirk: race clocks that keep their own time

The running events time a race by counting frames, not seconds. The dash adds a hundredth of a second every frame, so on a PAL machine, at 50 frames a second, its clock runs at half speed, and the disk's record of 9.72 seconds took about nineteen and a half to run. The relay adds 0.11 seconds every second frame, 2.75 seconds of race for each real one, so its record of 2:13.2 was run in under a minute (race_clock). The swimming clock adds a tenth every six frames, five-sixths of real time on PAL, and on an NTSC machine, at 60 frames a second, every clock runs a fifth faster than on PAL (sw_clock).

10 · The races

Secret: a debugging display, switched off

Every frame, the running events' main loop calls a routine that does nothing but return (rn_debug_off). The bytes after it are the routine that once ran there: it prints four bytes of the race's working memory in hexadecimal at the top left of the screen (rn_debug_hex). Turning the display off took one byte, an RTS written in front of it.

The swimming events keep a smaller trace of their testing: the raster interrupt writes the latest screen line it reached into two bytes at the top of memory, which the finished event never looks at (probe_frame). The pole vault keeps a routine with no caller, which switches the screen to text and jumps to $9000, where the finished event keeps the shapes of the bending pole (pv_unused).
