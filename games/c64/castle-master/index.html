Commodore 64 · 1990 · Domark

Castle Master

01 · Projection

A world through a small window

The view is assembled in a buffer that holds 120 rows of 30 bytes. Polygons are transformed into camera coordinates, clipped to the viewing volume, then projected onto that window.

A geometric illustration of $3C05: u = 60 + 60x/z. The point is rejected when it lies outside −z ≤ x ≤ z. The drawing uses real arithmetic; the game uses signed integer routines and clips polygons at their edges.

Depth changes how far a point appears from the centre. A point twice as far away moves half as far across the display. Clipping at $3B68 also checks the vertical coordinate and rejects points behind the camera.

02 · Inside the game

Seventy-two directions

The rotation table stores a sine and cosine for each five-degree step. Both are signed bytes scaled by 64. A value of 64 therefore represents one; the small integers make matrix arithmetic possible without floating point.

The arrow reads the actual pair at $123C plus twice the selected index.

How the transform uses it

Matrix multiplication at $36A9 rounds and rescales by 64. The point routine at $3730 applies the prepared matrix. Camera-position subtraction belongs to the caller.

03 · Inside the game

The menu becomes the view

The menu and the 3D picture share storage. The linear viewport at $87CC occupies the same span as menu material in the captured listing. During play, the painter at $3F76 fills it and $4B24 rearranges its bytes into the screen bitmap at $E528.

See the captured menu

The Source tab records this menu-time occupant. Reading that same RAM after play begins gives the rendered picture.

04 · Inside the game

Objects carry their own rules

The castle’s interactions are stored as condition streams. The dispatcher at $4A58 runs the object stream, then five global streams, then the current area stream. This gives an object a local response while still applying rules shared by the world.

A transfer that does not return

Opcode 48 changes the stream being executed. It does not save a return point in the outer stream. The length table at $13AE lets the interpreter step over other instructions.

05 · Inside the game

Saving the changing parts

The saved state is much smaller than the world database. Its payload combines the engine state with the object flags, so the fixed geometry can stay on the original disk.

Buffer reuse

The load buffer begins at $87CC, which is also used by the menu and the renderer at other times. Disk operations enter through $0423 and the device/file path at $7B03.
