Three switches beside the screen change the 3D view, the window above the cockpit's panel. Native resolution and Smooth motion change only how the page draws it: the game runs underneath as it does without them, and two copies of it, one with both switches on, keep every byte of memory the same at every frame. Fast CPU changes how fast the C64's processor runs, in space.

Native resolution

The game draws the view into the cockpit's multicolour bitmap, 126 pixels across and 103 down, each pixel twice as wide as it is tall. Many of its colours are patterns: two of the C64's sixteen colours in alternating pixels, which the screen blurs into a shade between them.

With Native resolution on, the page works the view out again from the numbers the game keeps at each pass it draws: where every object is and which way it faces, where the camera is, and how far the view is zoomed. It applies the game's own rules to them: which objects are in view, which are near enough for a model and which are drawn flat, the order from farthest to nearest, and which faces of each model turn towards the camera. Then it draws the same polygons, the same dots, rings and bursts, and the arrows that point to the target, as sharp shapes at the screen's own resolution. Each pattern becomes the shade the eye mixes from it.

Smooth motion

The game counts the frames its drawing takes and allows three for each pass. When a picture takes longer, the passes after it leave the drawing out, each paying back three frames, until the game has caught up (frame_skip3, $A470). So everything moves at every pass, and the view shows only some of the passes: in a fight it can change three times a second while the ships in it move nine times.

With Smooth motion on, the page draws the view at the screen's own frame rate, 60, 120 or 144 times a second. It keeps the numbers of every pass, the passes the game drew and the passes it left out, and draws each frame of the screen between two of them: every object and the camera part of the way from one pass to the next, and every turn part of the way round. In the chase and cinematic views the game moves the camera only at a pass it draws. For a pass in between, the page places the camera as the game would have: the chase camera at the same distance behind the ship, the cinematic camera where it was, each turned to face the ship.

The view keeps a little behind the game, so that the next pass is always there to move towards: by the longest gap between the last few passes. The C64's picture is behind the game too, since it shows the last pass drawn while the next one is being drawn, but by less. Over the same 23,100 frames the smooth view showed the game 44 milliseconds later than the C64's picture, on average.

What the game changes at once stays sudden: another view, a jump through a gate, a ship that arrives or is destroyed, and the dust that the game puts back near the camera as you fly on. Without Native resolution the page paints each view in the C64's pixels with the game's own drawing routines, run on a copy of its memory with the positions in between. At a pass the game drew, that picture is the game's own: in 468 such views every pixel of the window was the same.

Fast CPU

With Fast CPU on, the page flies the game as a C64 with a much faster processor would. In space the main loop goes round once every video frame, 50 times a second, and each pass draws a new frame into the game's own buffers and puts it on show, so every frame on screen is one the game drew.

A faster processor alone would make a faster game, since every pass moves everything in space a fixed step. Fast CPU keeps the game's pace instead, and the game says what that is: it allows three frames for each pass, and when its drawing takes longer it leaves the drawing out of the passes after, until it has caught up. So it means to move at 16.7 passes a second. Three of Fast CPU's passes stand for one of the C64's, and each takes a third of every step: of each ship's and missile's move, of each turn, of a planet's pull and an engine's thrust. The thirds go through the game's own movement code and add up to the C64's step exactly.

Where the C64 keeps up, cruising through empty space, Fast CPU flies at its pace or a little quicker. In a fight, with ships close by, the C64 falls behind its own three frames: it manages 8.4 to 11.1 passes a second, and everything in space slows down with it. A faster processor would not fall behind, so Fast CPU keeps the game's 16.7 there too.

What the game counts in passes happens once for each of the C64's passes: the computer ships' minds, the lifetimes of missiles and explosions, the cockpit's gauges, the hazards' dice, and the stick, which the game eases an eighth of the way toward where you hold it each pass. That easing is why a push of the stick still takes a moment to turn the ship. What the game times by its interrupt keeps its time, since the interrupt still comes 50.12 times a second: the sound, and the keyboard, which it reads into a buffer each frame with its own repeat. Each pass starts just after it, so a key shows in the next frame.

Your beam is drawn on the frame on show, so the C64 shows it while the next frame is being drawn, about three frames. With Fast CPU it is drawn on each of the three frames that stand for that pass. A ship's beam, the window's flash when you are hit, and a hazard's burst stay up for the same three.

Some things change with the finer steps. The game tests for contact after each third of a step rather than after each step, so a meeting the C64 would step past can count. The frames come at the C64's 50.12 a second: a display at 50 or 100 Hz shows each for the same time, and at 60 Hz one frame in five stays up for two refreshes. Navigation Control, the stations, docking and the jump through a gate run at the C64's own speed. Fast CPU and Smooth motion each give the view more frames than the C64 does, so switching one on switches the other off. Switched off, the game is the C64's again from where it stands.
