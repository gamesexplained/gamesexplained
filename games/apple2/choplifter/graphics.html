1982 · Broderbund Software · Apple II

Choplifter

The Apple II has no sprites. The helicopter, the hostages, the tanks and the jets are pictures from one table of 128 shapes, drawn dot by dot onto the hi-res screen by a graphics library of the game's own at $1000. Every picture on this page is drawn by that library, from the listing, on the kit's 6502.

01 · Everything that moves

Every moving shape, at the game's twelve frames a second

The game draws a whole new picture about twelve times a second, and each thing that moves takes its next picture once a frame. Here each one moves as the code moves it, in the colours the code draws it in.

The helicopter is drawn whole by its object's routine (heli_object, $8276), which draws the body, the main rotor and the tail rotor and steps each rotor's picture on. Everything else is drawn by calling the graphics library as the game calls it: gfx_colour, gfx_place, gfx_shape, gfx_clip_to_window, then the drawing routine the game uses for that shape, at the offsets and in the order the game's own routine for it uses (tank_impl, drone, draw_hostage, barracks, the flag and the jets' scripts). Each is drawn on the column the game would draw it on where the game fixes that column's evenness, because the hi-res screen colours a lone dot by its column.

Nothing on the screen has a colour of its own. A hi-res byte holds seven dots and one bit that picks a pair of colours: violet and green, or blue and orange. A dot lit alone shows the colour of its column, odd or even, in that pair; dots lit side by side show white. The library's whole and opaque drawing routines put one colour bit, g_colour ($8C), into every byte they write. The jets, the explosions, the muzzle flash, the drones' bodies, the flag and the fire are drawn that way with it set, in blue and orange; the tanks and the drones' spinning parts with it clear, in violet and green. The helicopter, its rotors, the hostages and the shots are drawn by OR, which leaves each byte's bit as the screen had it. The sky is black bytes with the bit set, $80, so over the sky they come out in blue and orange too, and where a hostage's feet reach the ground band, whose bytes have it clear, they turn violet and green.

Where a shape lands matters for the same reason. A shape one dot along shows its lone dots in the other colour of the pair, so the routine that places a jet, a drone, a tank or an explosion (object_place, $7B59) can push it one dot right to keep it on even columns or on odd ones, whatever the scrolling does. The hostages are placed so each keeps its own colours as the view scrolls.

The helicopter turning to face the viewer is drawn sheared, a row up or down every few dots (gfx_draw_slant), so five turning pictures and eleven side-on ones cover every pose at every tilt. How the tilt rocks it on its skids is on How it works.

02 · The shape table

One table of shapes draws everything, the lettering too

The 128 pointers at $A000 hold every shape the game draws. Those that move are above; here are the rest, the scenery, the counters' digits and the lettering, each drawn alone. Pick one to see what the listing says it is.

Pick a shape.

Each shape is drawn by the library on the sky's black the way the game draws it: whole or opaque with the colour bit the game gives it, copied as bytes, or by OR, which keeps the sky's bit. A shape starts with its width in dots and its height in rows, then its rows, top first, one bit a dot (gfx_shape). Seven, the four stretches of hills, the post office and the two barracks, are stored instead as seven copies already cut into screen bytes, one for each dot a byte can start at, and are copied straight onto the screen (gfx_copy_bytes, $1039).

The same table holds the title's lettering, the counters' digits and the three sortie messages, so the whole game, from "Broderbund Software presents..." to "THE END", is drawn by one set of routines. The library draws a shape in one of several ways: by OR onto what is there, opaque (every dot inside its box cleared first), mirrored left to right, sheared, or as a copy of ready-made screen bytes. The jets flying left, the hostages running left and the tank's shells are the same pictures drawn mirrored. A version that reports the first dot it lands on an already lit one is in the library too, and the game never calls it.

03 · How the screen is built

Each frame is erased box by box and drawn again on the page nobody sees

One frame of the demonstration flight, stopped before each thing the game draws. Step through it to watch the hidden page being built.

The demonstration flight is the game's own code run from start on the kit's 6502 (reference/demo.js), to its 268th frame. That frame is then run again stopped at each call to the library's drawing routines, at erase_old ($9B4C), twinkle_stars ($96AE) and draw_planet ($9411), and at gfx_show_page, which ends it. Each step shows the page after it, with the bytes it changed in yellow.

There are two hi-res pages, and the game draws on the one that is not being shown, then shows it and starts on the other (gfx_flip_page). The library EORs $60 into the high byte of every line address on page 2, which turns $20-$3F into $40-$5F, so every drawing routine serves both pages.

Nothing is cleared. Every shape drawn records a box in its page's erase list: a kind, its X and its row (add_erase, $7BF8). At the start of the next frame on that page, two frames later, erase_old fills each of those boxes, black above the ground line and the ground's pattern below it, so only what moved is touched. The ground band itself is never drawn: it is in the picture the disk loads onto both pages, and the erase boxes refill it with the same pattern, $55 $2A.

Two things are not shapes at all. The planet is draw_planet ($9411), 66 LDA # and STA pairs that store its bytes straight into screen memory, so the picture is in the code. The stars are fourteen bytes stored at 77 fixed places (store_stars1, $972D), two of them the same byte, and each frame twinkle_stars makes the bytes from two random numbers with each bit kept one time in four, so the sky twinkles.
