01 · Differences

What differs from a Commodore 16

  • The loading. There is none: the page starts where the tape's loader hands over, at the game's first instruction at $1AF4, the address that the tape's one line of BASIC, the C16's built-in language, calls with SYS 6900. That sets the machine up and shows the title.
  • The KERNAL. The KERNAL is the program built into the C16's ROM. TED's raster interrupt stops the game when the beam reaches a chosen line of the picture, and it goes through the KERNAL first. The KERNAL saves the processor's registers and jumps to the address held at $0314, the game's handler. The handler puts the registers back and returns by itself. The page does not carry the ROM. It calls the game's handler itself, and adds to its clock the cycles the ROM's code takes on the way in. The handler also calls the ROM's keyboard scan, which finds the key held and the SHIFT key for the game. The page runs the site's copy of that scan, the ROM's routine written again in JavaScript with the ROM's table of key codes, so the game sees the codes a C16 gives it. The few bytes of memory the ROM leaves set up for the scan, such as the length of each function key's text, are added to the game's memory as the C16 holds them when the game starts.
  • The screen. TED reads the screen's memory as its beam meets it. The page keeps a copy of the memory as each row of characters began, and TED's registers line by line, with each write taking effect on the line after the one it was made on. It draws the frame from those. The game's raster interrupt changes the background colours twice a frame: to the room's colours on line 250, for the top of the next frame, and to the panel's on line 146, below the room. The port makes those writes as its interrupt is taken, and the page puts each on the line where the game's own lands, from the cycles the game takes to reach it.
  • The interrupt. On the C16 the raster interrupt can come between any two instructions. On the page it comes between the port's steps: at each call main_loop makes, as a new game draws the lives, at each pause in the title, the death and the EGY bar's refill, and at each turn of a loop that waits for a key. The game's main program reads two bytes that the interrupt's keyboard scan writes, the key code and the SHIFT flag. On a C16 one of those can change between two of the main program's reads. On the page it cannot.
  • The random cannon. The cannon that fires either way chooses its side from TED's register $FF1F, whose lowest bit gives the line within its character row that the beam is drawing. The page reads it from its own clock, at about the place in the pass where the game's code reads it, so the cannon fires left or right as a C16 would on some run, never as one particular run did.
  • The sound. The game's writes to TED's sound registers, the tune on the title and the notes of the jumps, falls and deaths, go to the site's model of TED's two voices, made from the plus4emu emulator's, each write at the place in the frame where the page's clock made it.
  • Start a game. The game starts only from its own keys. One player and Two players press them for you: RETURN on the title, then F1 or F3 on the menu, the joystick choices. A keyboard game is F2 or HELP, which you can press yourself.
  • The cheats. Unlimited lives, Unlimited energy and Nothing kills him are Plus/4 World's pokes: the page writes the same bytes into the game's code, and the port reads its instructions there, so the game does what it does on a C16 with the same pokes.
  • The keys. The arrows and Space are the joystick in port 2, or, with a keyboard game chosen, the game's own keys: Z and X to walk, K and M, which the game reads and never uses, and SHIFT to jump. Enter is RETURN. The C16's F1, F2, F3 and HELP are the browser's F1 to F4, or 1 to 4, since some browsers keep the F keys for themselves. P pauses and D gives up a life, as on the C16.
