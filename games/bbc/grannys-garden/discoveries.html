1983 · 4Mation Educational Resources

Granny's Garden

An answer that fixes the magic tree, which nothing in the game mentions, and five bugs, the worst of which stops Part 1 of this disc before Tom can be found.

01 · Ready to start?

Secret: answer T before Y, and the magic tree is always a1

The game's first question, Ready to start?, takes one more answer than yes. Type T, then Y, and the magic tree is the bottom tree on the left, one the game never picks otherwise.

Line 220 asks the question until the answer begins with Y, and line 230, in the same loop, sets a flag, t%, when it begins with T. The question comes back with nothing said. Line 290 then picks the tree as usual and, if t% is set, puts it at column 4, row 12: a1. On How it works, the second button under the trees, Pick it after T, picks it that way (the magic trees). The flag is cleared each time the program starts again, so it holds for one game.

The flag has a variable of its own and a test of its own, so it was put there on purpose. Nothing on the screen mentions it, and neither does any review or guide to the game found online. The teacher's booklet that came with the game, which has not been found, may say what it was for.

02 · Memory

Bug: on this disc, Part 1 runs out of memory before Tom

Each program was written to move itself down to &0E00 when it is loaded higher, as a disc system's workspace makes it. On this disc that test is turned off, and Part 1, left at &1900, stops with No room before the end.

The bytes free between BASIC's variables and its stack at each of the game's waits, in jsbeeb, on the way to Tom. At &0E00 the run reaches Tom with about 2,200 bytes to spare. Loaded at &1900, as the disc puts it, the same answers stop at the pond with No room at line 2670.

The first line of each program was a test, IF PAGE<>&E00 GOTO 3280 (2590 in Part 2). The lines it goes to select the tape filing system, copy the program down to &0E00 four bytes at a time and run it there, which gives it 2,816 bytes more. The second line then writes a REM over the first, so that the program, running at &0E00, does not test again. Both files on this disc were saved after such a run: their first lines are REMs, and CHAIN runs each program where the disc system loads it, at &1900.

Part 1 has about 1,000 bytes there when it starts, and its variables and BASIC's stack need about 1,600 more as it goes. It stops at the pond, or on the stairs by the route through the house, and No room is the one error ON ERROR cannot catch (starting again), so the game ends at BASIC's prompt. Part 2 is smaller and runs to its end either way. Typing LOAD"GRAN1" and then GOTO3280 runs the program's own move and gets round it. Whether this is 4Mation's own disc is unknown; no other copy was compared.

03 · The giant

Bug: answer the giant "maybe" and the hill turns into the forest

The giant on the hill asks Shall I eat you?

After Maybe, then Y: the forest's words under the hill's picture. Played in jsbeeb on 14 October 2026.

PROCgiant asks again when the answer is neither yes nor no, by calling itself. When the inner call ends at Y, it returns to the end of the outer call's last line, line 2090, and BASIC carries on to line 2100. That line is DEF PROCfor, the forest, and BASIC passes over a DEF it meets on the way as though it were a REM, so it runs the forest's lines inside PROCgiant: the words about the creepy forest appear under the hill, no stone is offered, and the map then says the player is at the hill.

04 · The Giant's garden

Bug: call the bee in the wood and Tom can never be found

In the Giant's garden each creature helps at one stage of the way to Tom. The bee is the only one that can get past the Giant's dog, and if it was called in the wood before, it will not.

The stages are in Part 1 lines 2840-3060 ($5CAB). The route that calls the bee in the wood was played to the dog in jsbeeb.

Calling the bee in the wood sets be to 1 for the rest of the run. At the dog, only an unhurt bee chases the dog away, and every other creature brings the Witch, so a player who tried the bee in the wood can no longer reach Tom. The bee says it must go to the doctor, and the toadstool says You will have to try again., as it does after any creature that cannot help in the wood. Nothing says that the bee is needed later, and the dog is two stages on.

05 · Lost without being told

Bug: the Land of Mystery can be lost without the game saying so

The Land of Mystery has one key, one cake and one chance at the castle door. Three choices use one up, and the player can then walk the map for good without being able to finish.

Part 2: the lake at lines 2180-2330 ($5353), the castle at lines 1760-1800 and its keeper at lines 2470-2520, the forest and its tower at lines 2100-2160. The first two were played in jsbeeb; the third is read from the code.

The castle was meant to let a friend back in. Its flag fed%, which would say the keeper has been given the cake, is set FALSE at line 180 and never set TRUE, so the keeper's welcome for a returning friend, at line 2500, is never shown.

06 · DELETE

Bug: one DELETE too many and the answer no longer matches the screen

A DELETE pressed when the answer is empty still counts, and PROCi's count of letters falls one behind the screen. From then on each DELETE takes a letter too many off the answer, or none at all.

Keys at Ready to start?On the screenThe answerWhat happens
X DELETE Y RETURNYYthe game starts
DELETE X DELETE Y RETURNYXYReady to start? again
DELETE s n o x DELETE wSnowSnw

Typed in jsbeeb on 14 October 2026 at the first question of Part 1, the answer read from the game's variable in$. On How it works, the button Type DELETE, X, DELETE, Y above the black box types the second row (typing an answer).

PROCi, the input routine every answer goes through, keeps the number of letters in l, and a DELETE does l=l−1 and in$=LEFT$(in$,l). A DELETE in an empty field still counts, so l becomes −1, and stays one less than the letters on the screen. Each later DELETE cuts the answer to l letters, one fewer than the screen keeps; when l is below zero it cuts nothing, because BBC BASIC's LEFT$ with a negative length gives back the whole string (tried on its own: LEFT$("AB",-1) is AB). A child who presses DELETE once too often and then corrects a mistake sees the right word on the screen while the game reads another: Snow, typed that way at the password, is Snw, which holds no no.
